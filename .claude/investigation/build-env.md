## 1. Poetry layout & lock

- `poetry.lock` present (562 KB, mtime Jun 22); `poetry check` → `All set!` (lock is consistent with pyproject).
- Lock generated by **Poetry 1.8.4**. The Makefile self-heals a stale lock: `install_python_deps` runs `poetry check || poetry lock --no-update` (`Makefile:14,21,40-45`). **`--no-update` was removed in Poetry 2.x** (inferred from Poetry release notes, not verified here), so the Makefile lock-repair path and `make force_lock` assume Poetry 1.8.x. `kernel_runtime/Dockerfile:25` pins `POETRY_VERSION=1.8.4` explicitly; the core/worker Dockerfiles install *latest* Poetry unpinned (`curl -sSL https://install.python-poetry.org | python3 -`, `flowfile_core/Dockerfile:13`) — a future Poetry 2.x default could drift the Docker builds (inferred risk; the docker build only runs `poetry install --only=main --no-root`, which still exists in 2.x).
- Dependency groups: main (everything runtime), `dev` (pytest, mkdocs, ruff, testcontainers, psycopg2-binary, pymysql, numpy 1.26.4, mkdocstrings...; installed by default), `build` (**optional**; only `pyinstaller ^6.11.0`; needed for `make build_python_services` → install with `poetry install --with build`).
- Poetry scripts (`pyproject.toml:82-101`): `flowfile_core`, `flowfile_worker`, `flowfile`, `flowfile_scheduler`, `build_backends`, `build_backends_prd`, `flowfile-migrate`, plus Docker-fixture helpers `start_/stop_{postgres,mysql,minio,azurite,gcs,redpanda}`.
- Wheel/sdist includes bundle the built web UI: `flowfile/flowfile/web/static/**/*` and catalog demo YAMLs (`pyproject.toml:18-25`) — this is why the PyPI workflow must build the frontend *before* `poetry build`.

## 5. Signing & release (desktop)

### macOS notarization (SIGNING.md + tools/sign_macos_sidecars.sh + release.yaml)
- **The one big trap:** sidecars must be built with a **non-framework CPython** or notarization fails on `_internal/Python.framework/Python` ("signature of the binary is invalid"). Framework builds (actions/setup-python, Homebrew, macOS system python, conda) make PyInstaller bundle `Python.framework` with symlinks; `tauri build` **drops symlinks** copying `binaries/**/*` into the .app (tauri-apps/tauri#13219), breaking the `_CodeSignature` seal. Local repro recipe (SIGNING.md:101-113):
  ```bash
  export UV_PYTHON_PREFERENCE=only-managed
  uv python install 3.11
  poetry env use "$(uv python find 3.11)"
  python -c "import sysconfig; print(repr(sysconfig.get_config_var('PYTHONFRAMEWORK')))"  # must be ''
  poetry install --with build
  make build_python_services
  find services_dist/_internal -name 'Python.framework' -maxdepth 2   # must be empty
  ```
  Release CI enforces this with a fail-fast check (release.yaml:100-110).
- `tools/sign_macos_sidecars.sh` (run by `make sign_sidecars` / CI): no-op unless Darwin + `APPLE_SIGNING_IDENTITY`; deep-signs every Mach-O under `binaries/` with `codesign --force --timestamp --options runtime --entitlements entitlements.mac.plist`; phase 2 normalizes any `*.framework` back into canonical symlink layout (PyInstaller stages real-file copies → codesign "bundle format is ambiguous") and synthesizes a minimal `Info.plist` (CFBundlePackageType=FMWK) if missing; exits 1 on any signing failure.
- Required CI secrets (SIGNING.md tables): `TAURI_SIGNING_PRIVATE_KEY(+_PASSWORD)` for updater; `APPLE_CERTIFICATE(+_PASSWORD)`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` (app-specific), `APPLE_TEAM_ID` for notarization; `WINDOWS_CERTIFICATE(+_PASSWORD)` for Authenticode (skippable — unsigned NSIS installers work with a SmartScreen warning).
- Updater keypair: `cargo tauri signer generate -w ~/.tauri/flowfile.key`; the pubkey is committed in `tauri.conf.json plugins.updater.pubkey`. Updater manifest `latest.json` must be **manually assembled and attached** to the GitHub release — release.yaml ends with a `::notice` reminder; it references `tools/make_latest_json.py` "(or equivalent)" but **that script does not exist** in `tools/` (verified listing). Schema in SIGNING.md:40-55.
- `release.yaml` matrix: macos-14 (aarch64), macos-15-intel (x86_64), windows-latest, ubuntu-22.04; Node 20, Python 3.11, Rust stable + Swatinem/rust-cache; version-sync gate `check_version_sync.py --expect ${tag#v}`; linux needs `libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev patchelf` etc.; macOS quirks: `echo "/usr/bin" >> $GITHUB_PATH` to prefer system `xattr`, and macOS updater bundles `Flowfile.app.tar.gz` are renamed per-arch (`Flowfile_aarch64.app.tar.gz` / `Flowfile_x64...`) because arm+intel artifacts have identical names and collide as release assets (symptom: misleading 404 from action-gh-release on 2nd upload) — renaming is safe because the signature signs contents not filename (release.yaml:148-170). Tags containing `-` (rc/beta/test) auto-mark as prerelease.
- Pushing a `v*` tag fires BOTH `release.yaml` (installers) and `pypi-release.yml` (PyPI). `pypi-release.yml`: Node 20 builds `npm run build:web`, copies `build/renderer/*` → `flowfile/flowfile/web/static/`, then `poetry install; poetry build`, publish via PyPA action with `skip-existing: true`, environment `pypi` (trusted publishing, id-token: write).

### Master key
- Runtime resolution order (`flowfile_core/flowfile_core/auth/secrets.py:150-222`): `FLOWFILE_MASTER_KEY` env (validated as Fernet key) → Docker secret file `/run/secrets/flowfile_master_key` → electron mode: auto-generate + store in local `SecureStorage` (APPDATA/`~/.config/flowfile`; non-electron fallback path `SECURE_STORAGE_PATH` default `/tmp/.flowfile`) → otherwise RuntimeError telling you to set the env/secret.
- `make generate_key`'s repo-root `master_key.txt` is **not read by the app runtime** — no runtime code reads that path (grep verified; only project/manifest.py excludes it from exports and test-docker-auth.yml writes its own). It's operator convenience for wiring a Docker secret / env. Gitignored (`.gitignore:79`, plus `*.key`, `*.pem`, `.env`).

## 7. Gotchas & traps (each verified as described above)

1. **Stale poetry.lock self-heal assumes Poetry 1.8.x** — `poetry lock --no-update` (Makefile:14/21/36) is a 1.x flag. Lock header says Poetry 1.8.4; kernel Dockerfile pins 1.8.4; core/worker Dockerfiles install unpinned Poetry (drift risk, inferred).
2. **Sidecar staging order is rigid:** `build_python_services` → `rename_sidecar.py` (needs `rustc` for the triple) → (sign) → tauri build/dev. `npm run dev` with unstaged binaries starts a shell with no backend, no error at build time.
3. **`build_tauri_win/_mac/_linux` targets skip lint + vue-tsc** (they call `npx tauri build` directly; only `build_tauri_app` runs `npm run build` with checks) and skip `npm install`.
4. **macOS notarization requires non-framework CPython** (uv python-build-standalone) — conda/Homebrew/setup-python Pythons produce bundles that fail notarization after Tauri's symlink-dropping resource copy. Check `PYTHONFRAMEWORK` is empty before building release sidecars.
5. **Stale DMG mounts break `tauri build` on macOS** — `make clean_dmg_mounts` (auto-run by the mac build targets) force-detaches `/Volumes/Flowfile*`.
6. **`make test_e2e` starts core but NOT the worker**, swallows Playwright failures (`|| true`), and `stop_servers` pkills anything matching `vite`/`flowfile_core` (on Windows: ALL python.exe/node.exe).
7. **`make generate_key`'s master_key.txt is not consumed by the app** — runtime key comes from `FLOWFILE_MASTER_KEY` env, `/run/secrets/flowfile_master_key`, or electron SecureStorage. Compose has no `secrets:` block; env wins over the secret file.
8. **PyInstaller hiddenimports are load-bearing:** removing `polars_simed`/`polars_distance` breaks startup (transitive deps of pl_fuzzy_frame_match); `polars_ds` is lazily imported (static scan misses it); litellm/tokenizers/tiktoken_ext need explicit collection; connectorx needs the metadata runtime hook.
9. **DB drivers are dev-group-only** (`psycopg2-binary`, `pymysql` in `[tool.poetry.group.dev]`) — the Docker images pip-install them explicitly (`flowfile_core/Dockerfile:30`); a "prod-deps-only" local install (`poetry install --only main`) lacks Postgres/MySQL drivers.
10. **Frontend and WASM are on different Vite/Vitest majors** (6/3 vs 8/4) — don't copy config between them blindly.
11. **Pyodide pinned to 0.27.7 (CDN, not npm)** — last release with Polars support; version appears in `pyodide-store.ts`, the smoke-test CI install, and the pinned CPython test requirements; bump all together.
12. **Vite dev proxy must replicate FastAPI's absolute 307 redirects** (vite.config.mjs proxy.configure / nginx `proxy_redirect` default) — trailing-slash mismatches silently break only in Docker.
13. **`strictPort: true` + `optimizeDeps.force: true`** — dev server dies if 8080 is taken (intentional); cold starts re-bundle (~5-15s).
14. **`.env` is gitignored, `.env.example` is the template**; compose ships insecure defaults (`admin`/`changeme`, dev JWT/internal tokens) that must be overridden in prod; `JWT_SECRET_KEY` and `FLOWFILE_INTERNAL_TOKEN` are startup-required in docker mode.
15. **Kernel lite-flavour constraint whitelist** (Dockerfile grep line 47) must stay in sync with `_LITE_PACKAGE_NAMES` in `flowfile_core/kernel/flavours.py`; core resolves baked kernel versions by parsing `kernel_runtime/poetry.lock` at runtime (`flavours.py:16-18`) — the lock file ships in the core image via `COPY tools`? no — actually via repo layout in dev; **inferred**: in the Docker image `kernel_runtime/poetry.lock` is absent (only `shared`, `tools`, core, scheduler, flowfile, frame are COPYed) so `flavours.py` logs "Kernel poetry.lock not found" and falls back — not verified beyond the warning branch existing.
16. **`v*` tag fires two workflows at once** (PyPI + desktop release); wasm publishes are `wasm-v*`; version bumps must go through `make bump-version VERSION=X.Y.Z` or CI's `check_version_sync.py --expect` gate fails the release.
17. **Root leftovers that are NOT the build system:** `main.spec` (legacy, snowflake-era), `connectorx_hook.py` (generated at build), `build_backends_prd` (a benchmark, not a prod build), `scripts/` (only `__pycache__`), root `node_modules`/`package-lock.json` (stray).
18. **CLAUDE.md drift:** version 0.11.0 (actual 0.12.7), `docker-remote/` (never existed in git), "12 workflows" (15 files present incl. codeql.yaml, claude.yml, claude-pr-review.yml).
19. **PyPI wheel must contain the built frontend** — `poetry build` without first building `npm run build:web` + copying into `flowfile/flowfile/web/static/` produces a wheel whose `flowfile run ui` has no UI (include paths at pyproject.toml:18-25; the copy step lives only in pypi-release.yml).
20. **`flowfile` package import sets env vars** (`FLOWFILE_WORKER_PORT=63578`, `FLOWFILE_SINGLE_FILE_MODE=1` at `flowfile/__init__.py:17-18`) — importing `flowfile` in the same process as a normally-configured core/worker silently rewires ports.
