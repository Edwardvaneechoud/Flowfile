# CLAUDE.md - flowfile_frame

A Polars-like programmatic Python API that builds Flowfile ETL graphs under the hood. Package-specific notes; see the root `/CLAUDE.md` for monorepo-wide setup, build, lint, ports, and cross-package contracts.

## Role
`flowfile_frame` (imported as `import flowfile_frame as ff`) is a Python library giving a Polars-`LazyFrame`-like surface (`FlowFrame`, `Expr`/`Column`). Every method call appends a node to an **in-process `FlowGraph`** instead of (only) computing data.

It is **NOT independent of the backend**: it imports `flowfile_core` directly (`flowfile_core.flowfile.flow_graph.FlowGraph`, `flowfile_core.schemas.*`, `flowfile_core.database.connection`) to construct/mutate the same DAG the Designer UI and core executor use. It runs in-process — no HTTP, no ports. The graph it builds can be saved (`.flowfile` via `save_graph`) and opened in the Designer, or executed via `.collect()`.

Runtime contract: each `FlowFrame`/`Expr` carries a `_repr_str` — a literal Polars source-code string. Complex operations are serialized into graph nodes via the `_add_polars_code` path in `flow_frame.py` (which calls `flow_graph.add_polars_code`); simple ones map to dedicated node settings (`add_sort`, `add_manual_input`, etc.). The generated string must be valid, executable Polars code, since core re-evaluates it.

## Layout
- `flowfile_frame/flow_frame.py` — `FlowFrame` class; node emission, `collect`, `save_graph`, `to_graph`, writers.
- `flowfile_frame/expr.py` — `Expr`, `Column`, `When`, `col`/`lit`/`when`/aggregations; `_repr_str` machinery, `.str`/`.dt` namespaces. `add_expr_methods(Expr)` is invoked at module end.
- `flowfile_frame/flow_frame_methods.py` — module-level constructors/readers: `from_dict`, `from_raw_data`, `read_csv`, `read_parquet`, `read_excel`, `scan_csv`/`scan_parquet`/`scan_delta`, `concat`, cloud scans.
- `flowfile_frame/lazy_methods.py` — `add_lazyframe_methods` decorator (applied to `FlowFrame`) + `PASSTHROUGH_METHODS` (e.g. `collect`, `schema`, `columns` delegate to the cached Polars object).
- `flowfile_frame/adding_expr.py` — `add_expr_methods` decorator injecting Polars-mirroring methods onto `Expr`.
- `flowfile_frame/selectors.py`, `expr_name.py`, `list_name_space.py` — selectors and `.name`/`.list` namespaces.
- `flowfile_frame/group_frame.py`, `join.py`, `series.py`, `lazy.py` — group-by, join inputs, `Series`, `fold`.
- `flowfile_frame/database/` — DB connection helpers + `read_database`/`write_database` (`database/frame_helpers.py`); delegates to `flowfile_core.database` / core's connection manager.
- `flowfile_frame/cloud_storage/` — S3/cloud connection helpers + `read_from_cloud_storage`/`write_to_cloud_storage` (`cloud_storage/frame_helpers.py`).
- `flowfile_frame/catalog.py`, `catalog_reference.py`, `kafka.py`, `rest_api.py` — catalog I/O, Kafka, REST sources.
- `flowfile_frame/callable_utils.py`, `utils.py` — lambda-source extraction; `create_flow_graph()` factory that seeds a fresh `FlowGraph` (local execution, history off).
- `flowfile_frame/native.py` — `NativeNodeError` (a `ValueError`), the `NativeNode` base (`_build`), the generic `Node`, `DEFERRED_NODE_TYPES`, and the helpers fluent code shares with it: `merge_frames`, `allocate_node_id`, `add_connection_checked`, `seed_deferred_node` / `seed_from_predicted_schema`, `is_side_effect_node_type`, `seeded_at_build`, `ancestors` (the one lineage walker; `follow=` narrows it) and `_kernel_id` (`kernel=` normalisation for `PythonScript` and `CustomNode`).
- `flowfile_frame/gate.py` (`Gate`), `parameters.py` (`Parameter`, `add_flow_parameter` / `set_flow_parameter`, `refuse_parameter_as_column`, `contains_parameter`, which `adding_expr.refuse_parameter_argument` uses to refuse a `Parameter` argument to an `Expr` method), `run_flow.py` (`FlowInput`, `FlowOutput`, `FlowRef`, `flow_ref`, `register_flow`, `RunFlow`; `FlowFrame.to_flow_output` delegates here), `custom_node.py` (`CustomNode`, `CustomNodeFactory`, `custom_node`), `python_script.py` (`PythonScript`, `PythonScriptFunction`, `python_script`) — the native node classes, one canvas node each.
- `flowfile_frame/enums.py` — `GateOperator` / `ParamType` / `NodeTypes` `(str, Enum)` companions of the `GateOperatorLiteral` / `ParamTypeLiteral` / `NodeType` literals, plus `_literal()` (enum member → plain value). `tests/test_enums.py` pins each set against core.
- `*_stub_generator.py` (package root) — three generators that introspect source to emit `.pyi` stubs.

## Key patterns & conventions
- **Source string is load-bearing.** When adding/altering an `Expr` or `FlowFrame` method, ensure `_repr_str` builds correct Polars code (use `pl.` prefixes for dtypes/classes, mirror Polars signatures). A wrong string breaks graph execution silently.
- **Two emission paths.** Prefer a dedicated core node setting when one exists; fall back to `_add_polars_code` only for genuinely complex expressions (`use_polars_code_path` flags in `flow_frame.py`).
- **`drop`, `filter` and `when` lower natively.** `drop(names)` → `NodeSelect` with the dropped columns `keep=False` and `keep_missing=True` (selectors, or a missing name under `strict=True`, stay on the Polars-code path). `filter(*predicates, **constraints)` → `NodeFilter(advanced)` when every predicate has an `_ff_repr` (comparisons, `&`/`|`/`~`, `is_in`, `is_null`, the mapped `.str`/`.dt` helpers), joined with `and`; `filter_split` reuses the same predicate text and raises `ValueError` when there is none (no Polars-code fallback for a two-output node). `When` keeps an `if … then … elseif … else … endif` `_ff_repr` (no `otherwise` ⇒ `else null`), so `with_columns([when(...)...alias(x)])` becomes a Formula node. Every lowering first runs `_formula_parses` (core's parser accepts the text) because a Filter node silently keeps nothing on a parse error; string literals take whichever quote kind the value lacks — the parser has no escape, so a value with both kinds has no formula form. Polars-code nodes emitted without a `description` get a derived label (`Add columns: x`, `Filter on: a`, `Sort by: a`) instead of the UI's truncated first code line. Tests: `tests/test_native_nodes.py`.
- **`with_columns` emits at most one Formula node.** Expressions that all have an `_ff_repr` become ONE `NodeFormula` with one entry per expression, in argument order — but only when they are *independent* (`flowfile_core.flowfile.formula_dependencies.entries_are_independent`: no expression reads a column another writes; reading the column it writes itself is fine, an unparseable formula fails closed). Formula-node entries evaluate SEQUENTIALLY while Polars' `with_columns` evaluates in parallel, so dependent expressions (`(col("x")+1).alias("x")` beside `(col("x")*2).alias("y")`) skip the formula path entirely and emit a Polars-code node, preserving Polars semantics. The `flowfile_formulas=` kwarg is the sequential contract by design and always emits one multi-entry node (`_with_flowfile_formulas`), no independence check. **The two directions are deliberately asymmetric**: import collapses independent expressions into one N-entry node, while export always chains one `with_columns` call per entry (`code_generator`), so a multi-entry node re-imports as N single-entry nodes rather than round-tripping as one. Tests: `tests/test_with_columns_multi_entry.py`.
- **Partition aggregates lower onto the Window node.** `Expr.over()` records a structured `_window_spec` (`{column, function, partition_by}`) when the base is exactly `pl.col(x).<agg>()` with `agg` in `transform_schema.AGGREGATE_WINDOW_FUNCTIONS`, the partition is plain unaltered columns, and no `order_by`/`descending`/`nulls_last`/non-default `mapping_strategy` was given; `alias()` carries it, any other method drops it. `FlowFrame.with_columns` → `_try_native_window_functions` emits one `NodeWindowFunctions` when every expression has a spec, all share the same `partition_by`, and every output name differs from its source column (the node's schema callback appends columns, so an unaliased overwrite stays on the polars-code path). Tests: `tests/test_window_lowering.py`.
- **Methods are injected**, not all hand-written: `FlowFrame` is decorated with `@add_lazyframe_methods`; `Expr` via `add_expr_methods(Expr)` at module end. Passthrough methods (`PASSTHROUGH_METHODS`) just delegate to the cached Polars object; explicitly-defined methods (e.g. `collect`) are never overwritten by the decorator.
- **Native node classes and deferred frames.** Node types with no fluent method are placed by classes on the `NativeNode` base (`native.py`); user docs: `docs/users/python-api/reference/native-nodes.md`. Invariants:
  - `_build` follows canvas order: `merge_frames` (only when flow ids differ; remaps the passed frames in place and leaves other graph handles stale) → `allocate_node_id` (never behind the process counter or the graph's max id; `add_node_step` silently replaces a same-id node) → settings with the base-managed fields (`flow_id`, `node_id`, `pos_x/pos_y=0.0`, `is_setup`, `user_id`, `depending_on_id(s)`) → promise → wire → `graph.add_<type>` (keyed-input nodes such as `run_flow`: add first, then wire) → add-time diagnostics → one frame per output handle, named from the settings' `output_names`. A failed build deletes the node again. Subclasses customise it through hooks, not by overriding `_place`/`_build_outputs`: `_add` (the add call; `CustomNode` uses `add_user_defined_node`), `_seed_schemas` (per-handle seed schemas; `RunFlow`, `CustomNode`) and `_build(handles=...)` (explicit target handles; `RunFlow`'s keyed slots).
  - **Building never runs a deferred node.** `DEFERRED_NODE_TYPES` (run_flow, python_script, GA/external sources), kernel and prediction-blocked custom nodes, local custom nodes on a non-local graph, and side-effect nodes (`is_side_effect_node_type`: `output`-group templates plus the model nodes) below a deferred frame or a gate are **seeded** with typed zero-row outputs (`seed_deferred_node`: `resulting_data`, `_named_outputs`, `_named_schemas`, `deferred_until_run=True`) instead of executed; `seeded_at_build` is the one predicate `_create_child_frame` and `NativeNode` share (the gate walk runs only for side-effect types), so a writer below a gate writes when the run reaches its live side. `FlowFrame._deferred` propagates through `_create_child_frame` and every multi-input op (`any(...)` of the inputs); `combine_flow_graphs_with_mapping` carries seeds, and every built or run result, across a merge (a node that already ran has lost its flag, and must not re-execute on the merged graph).
  - `collect()` and the materialising passthroughs (`MATERIALISING_PASSTHROUGH_METHODS` in `lazy_methods.py`) on a deferred frame call `_materialised_lazyframe`: `run_graph()` on the whole graph, success judged on the node's lineage only, a dead gate exit read from `flow_graph._last_closed_gate_handles`. Frames below a gate (`_below_a_gate`: the node or an ancestor is a gate) take the same run-then-read path; only frames with no gate and no deferred ancestor collect their build-time plan.
  - A seed lost to an in-place reset (settings change, re-wire) surfaces as core's `DeferredNodeError`, translated by `lost_placeholder_error`; build-time-effect paths on deferred frames (`sink_*`, `inspect`, Polars-code writer and serialize fallbacks) raise instead of baking the placeholder into a node.
  - **Build-time reads go through `native.materialise`** (every `get_resulting_data`/`get_output` a frame is built from), so `${name}` resolves like the run loop (`node_parameters_resolved`) — for the node and every result-less ancestor the read re-executes (after a merge or `FlowGraph.reset()`) — and an undeclared reference raises `NativeNodeError`, even on a graph without parameters. It also translates a lost placeholder's `DeferredNodeError`.
  - Every user-facing error is `NativeNodeError`; translate FastAPI `HTTPException` (e.g. via `add_connection_checked`), never let it escape.
  - **`@python_script` cell layout is a contract.** `python_script._notebook_cells` emits, in order and each only when non-empty: the prelude (imports of modules the body reads from its module, then constants) / the inputs cell (`INPUTS_MARKER` `# flowfile: inputs`, then `<param> = flowfile_ctx.read_inputs()["main"][i]` per parameter) / the docstring as a `#` note / the body split at `# %%` and `# %% [markdown]`, dedented / the last cell, where the top-level `return` becomes `OUTPUTS_MARKER` `# flowfile: outputs`, `_result = <expr>` and the publish (`flowfile_ctx.publish_output(_result, "<output>")`, or the key-checked loop for a dict). The planned canvas→code export (a Python Script node back into a function) pattern-matches this layout and the two marker comments, so change them only together with it. Tests: `tests/test_native_python_script.py`; `docs/examples/native_nodes.py` pins the documented example's cells verbatim.
  - **Import-cycle rule:** `native.py` must not import `flowfile_frame.flow_frame` at module level (`flow_frame` imports from it); import `FlowFrame` inside functions or under `TYPE_CHECKING`, as `_build_outputs` does.
- **Polars re-exports.** `__init__.py` re-exports Polars dtypes and aliases `LazyFrame = DataFrame = FlowFrame` for generated-code compatibility — keep these when touching exports.
- Follow root-doc rules: Polars only (never pandas); imports ordered stdlib → third-party → first-party.

## Running / entry points
Library only — no server/CLI of its own. Usage: `import flowfile_frame as ff`, build a graph, then `frame.collect()` (returns `pl.DataFrame`), `frame.save_graph("p.flowfile")`, or `open_graph_in_editor(frame.flow_graph)` (from `flowfile.api` in the `flowfile` package). Backend modules load in the same process; no port is bound.

```bash
poetry run pytest flowfile_frame/tests
```
Tests live in `tests/` (`test_flow_frame.py`, `test_expressions.py`, `test_ff_repr.py`, `test_joins.py`, etc.). `tests/conftest.py` sets `TESTING=True` and provisions a MinIO cloud connection (`minio-flowframe-test`, expects MinIO on `localhost:9000`). Docker-dependent tests use `@pytest.mark.skipif(not is_docker_available(), ...)` (helper in `tests/utils.py`). There is no `frame`-specific pytest marker in root `pyproject.toml` (see `[tool.pytest.ini_options]` for the registered set).

## Gotchas
- **Stub gate.** Public surface of `FlowFrame`/`Expr`/submodules ships committed `.pyi` stubs (+ `py.typed`). After any public API change run `make stubs` (root) and commit; `make check_stubs` is the CI gate that fails on drift. All three generators run from `make stubs`: `expr_stub_generator.py` → `expr.pyi`, `flow_frame_stub_generator.py` → `flow_frame.pyi`, and `submodule_stub_generator.py` → every other `.pyi` **including `__init__.pyi`** (it walks all `.py`, excluding only `expr.py`/`flow_frame.py`). `make stubs` then runs `ruff --select F401 --fix` to prune unused imports.
- **Stubs of the native node modules.** `enums`, `native`, `gate`, `parameters`, `run_flow`, `custom_node` and `python_script` get their `.pyi` from `submodule_stub_generator.py`, which copies annotations verbatim (the `Literal`s reach the stubs), keeps `@property` but drops other decorators, renders enum members, and drops every dunder outside `_PUBLIC_DUNDERS` (`__init__`, `__call__`, `__getitem__`, `__iter__`, `__len__`): public classes need an explicit `__init__`. `__init__.pyi` leaves out the `from . import <sub>` re-export of a submodule shadowed by a same-named export (`custom_node` and `python_script` are the functions). A new `.pyi` must be `git add`ed — `make check_stubs` only diffs tracked files.
- Don't break the `LazyFrame`/`DataFrame` aliases or Polars dtype re-exports in `__init__.py` — generated flow code depends on them.
- Per the user memory rule, core must not `.collect()` LazyFrames internally; `FlowFrame.collect()` here is the intended user-facing materialization point.
- DB/cloud/catalog helpers persist via `flowfile_core` (`get_db_context`, core's connection manager) — they touch core's storage, not a local file.
- **Cloud Delta mirrors the catalog's merge/change-feed kwargs, minus cursors.** `FlowFrame.write_delta` / `write_to_cloud_storage` take `merge_keys` and `track_changes` (Delta-only guards like `partition_by`'s), and `scan_delta` / `read_from_cloud_storage` take `changes_since` + `include_change_preimage` through `catalog._resolve_change_mode`; `changes_since="last_run"` raises for cloud paths (no cursor store) and `version`/`delta_version` plus `changes_since` is a `ValueError`. Cloud writes run when the method is called, not at `.collect()`.
