# CLAUDE.md - flowfile_core

Central FastAPI backend and DAG execution engine for Flowfile: manages flows as DAGs, runs node compute on Polars, hosts auth/catalog/secrets/AI/kernel subsystems, and offloads heavy work to `flowfile_worker`. Package-specific notes only; see the root `/CLAUDE.md` for monorepo-wide setup, build, lint, ports, and cross-package contracts.

## Role
- The hub of the system. The frontend (Tauri/web) and `flowfile`/`flowfile_frame` clients hit its REST API on **port 63578**; it calls `flowfile_worker` (63579) for compute, the kernel containers (Docker SDK) for sandboxed user code, and `flowfile_scheduler` for cron runs.
- App is `flowfile_core/main.py:app`; entry `flowfile_core.main:run` (poetry script `flowfile_core`). Also runs a saved flow in-process via `python -m flowfile_core.main --run-flow <path> --run-id <id>` (PyInstaller / CLI path; forces `OFFLOAD_TO_WORKER.set(False)` and `execution_location="local"`, drops UI-only `explore_data` nodes). `--run-id` is required.
- **Core compute contract:** core never materialises full LazyFrames for dataset memory. With `OFFLOAD_TO_WORKER` on (default; `FLOWFILE_OFFLOAD_TO_WORKER=1`) and a node's `execution_location != "local"`, full-dataset compute/writes go to the worker (it owns dataset memory in spawned subprocesses); core ships paths/JSON. Bounded `.collect()` on previews (head/`pl.len()`/sampling) inside `flow_data_engine.py` is allowed — don't add full-frame collects in core.

## Key patterns & conventions
- **Router wiring is centralized:** add endpoints by including the router in `main.py` (order/prefixes there are load-bearing — e.g. `ai_admin_router` mounts on `/system`, not `/ai`, so admins can flip the gate). Most editor routes carry `Depends(get_current_active_user)`; `public_router` and `flow_api.data_router` are API-key-authenticated (`verify_api_key`) instead.
- **AI gate:** the whole `/ai/*` router is gated by `FEATURE_FLAG_AI` (live-mutable `MutableBool` in `settings.py`; `ai/feature_flag.py` `is_ai_enabled`/`require_ai_enabled`, returns 503 when off). The `/system` admin route flips it without restart.
- **Keep the `ai` package litellm-import-free at module level.** Every `import litellm` is lazy (inside functions): `ai/providers/_litellm_base.py` and `ai/scheduler.py` (`from litellm import exceptions`). `ai/__init__.py` `setdefault`s `LITELLM_LOCAL_MODEL_COST_MAP=True` before any lazy import. Re-adding an eager litellm import breaks `test_classification`/`test_dry_run` lazy-contract tests. BYOK key wiring lives in `ai/byok.py` (reads `ai/credentials.py`, sets provider env vars litellm picks up); providers registered in `ai/providers/registry.py`.
- **Secrets format:** `encrypt_secret(secret_value, user_id)` → `$ffsec$1$<user_id>$<fernet_token>`; key is `HKDF-SHA256(master_key, info="user-<id>")`. The embedded user_id lets the worker decrypt without user context; legacy raw-Fernet tokens still decrypt via the `user_id` param.
- **API-key hashing is deliberate SHA-256** (`auth/api_key.py:hash_api_key`) — 256-bit random tokens, not passwords; don't "upgrade" to a KDF (the CodeQL weak-hash alert here is a known false positive). Passwords use bcrypt (`settings.PWD_CONTEXT`).
- **Kernels:** `kernel/manager.py` allocates host ports from **19000–19999** (`_BASE_PORT=19000`, `_PORT_RANGE=1000`) per container; image flavours (`ImageFlavour.BASE/ML/LITE/CUSTOM`) resolve their package inventory from `kernel/kernel_image_manifest.json`, generated from `kernel_runtime/{pyproject.toml,poetry.lock,Dockerfile}` by `tools/generate_kernel_manifest.py` and read package-relative in `kernel/flavours.py`. Image *tags* live in `kernel/images.py` (docker-free, so `matching.py` can read them without pulling in the docker SDK); `manager.py` re-exports them. **How a kernel reaches core is `kernel/urls.py::core_base_url` and nowhere else** — both `_build_kernel_env`'s `FLOWFILE_CORE_URL` and `execution.py`'s `/raw_logs` callback go through it, keyed on `_docker_network` (the kernel resolves core by service name only when it was joined to core's network) and using `settings.SERVER_PORT`, never a literal. Two independent constructions with a hardcoded `63578` in one of them is how the desktop app, which port-scans for a free pair, ended up sending a kernel's API callbacks to a different process than its log callbacks. **Startup GC is fail-closed and ownership-scoped.** `_restore_kernels_from_db` returns whether the registry is authoritative; when it isn't, `__init__` skips the orphan-container reap and the derived-image GC entirely (adoption still runs — it only adds knowledge). One swallowed DB error used to leave `_kernels` empty and the GC passes read that as "nothing should exist", destroying every container and image. Containers now carry ownership labels: `flowfile_core_instance` (which install, stable) and `flowfile_core_runtime` (which *process*, per-boot). Reaping needs the install label plus a 10-minute age grace; `shutdown_all` stops only kernels in `_started_here` — the DB-shared registry also lists kernels another core started, and tearing those down is how quitting the desktop app killed a dev core's kernels. `FLOWFILE_KERNEL_GC=0` disables reclamation outright. Shutdown duty transfers on adoption when the owning pid is gone (`_claims_ownership`, reusing `shared/run_completion._pid_is_alive` — `os.kill(pid, 0)` kills on Windows, so never probe by hand), so a hard-killed core doesn't leak its containers forever while a *live* owner keeps its own. Pre-label containers and pids recycled across a reboot leak instead; that direction only leaks, never kills another core's kernel (`make clean_kernels` is the manual sweep). The `get_kernel_manager` singleton is lock-guarded and warmed by a best-effort daemon thread at startup (`FLOWFILE_KERNEL_WARMUP`, default on; forced off in `tests/conftest.py` so TestClient lifespans never touch Docker). Starts are **single-flighted** per kernel (`_start_flights`) and container creation converges on name conflicts via a bounded create-or-adopt loop (`_create_or_adopt_container`: adopt the holder if it runs the desired image ID, else replace it). Execution is **serialised per kernel** (`_exec_locks`, one cell at a time) because the runtime execs cells into a shared namespace in one interpreter — concurrent cells race imports; `/interrupt` deliberately takes no locks so a running cell can always be cancelled. **Cancellation is addressed to an execution, never to a kernel**: every `ExecuteRequest` carries a server-minted `exec_token` (`build_execute_request` for flow runs, `execute_sync` for everything else; the `/execute[_cell]` routes blank any client-supplied value), `_active_execs[kernel_id]` records which token holds the exec lock, and `interrupt_execution_sync(kernel_id, exec_token)` refuses to fire unless that token is the one running. Without this a flow queued behind another flow on a shared kernel cancels the *other* flow's cell — `FlowNode.cancel` must always pass its own token, and the kernel's `/interrupt` binds the token to that cell's generation (a token whose cell already finished interrupts nothing rather than falling back to the newest cell). **Dependency matching** (`kernel/matching.py`, `packaging`-based, pure): `POST /kernels/match` (and the digest form `POST /kernels/match/batch` powering list-view readiness badges) ranks the caller's kernels against a custom node's pip specs (version-aware; a kernel "provides" = manifest packages for its flavour ∪ requested `packages` names ∪ `resolved_packages`) and returns a create-from-spec `KernelConfig` seed (ML flavour inferred from dep names, slugified collision-free id); it **degrades to DB-persisted kernels when Docker is down** — no 503. At run time `flow_graph._execute_on_kernel` pre-checks a kernel-env custom node's deps (`verify_kernel_for_node` → typed `KernelDependencyError`); only *provable* mismatches block — unverified versions, unknowable images, and invalid specs never do.
  **A kernel whose contents can't be enumerated is `level="unknown"`, never `"full"`.** That covers a custom image, a flavour repointed by `FLOWFILE_KERNEL_IMAGE_*` to a different release than the manifest describes, and a missing manifest. Collapsing that into `full` is what made every packaged install report "✓ has all packages" for kernels that had none, so keep `unknown` distinct from `unverified` (which means the image *was* enumerated and the name was found, but the version or extras aren't provable). `tests/test_kernel_packaging_gate.py` keeps the missing-manifest case unreachable in shipped artifacts; `tests/test_kernel_dependency_gate.py` (`-m kernel`) checks the manifest against a real `pip list` inside the image.
- **Migrations auto-run on import:** importing `flowfile_core.database.init_db` runs `database/migration.py:run_startup_migration` at module level (skipped when `FLOWFILE_SKIP_STARTUP_MIGRATION` set), handling fresh-install, legacy `flowfile.db` copy, and pending-migration cases. `init_db()` itself then seeds default users/catalog. Add schema changes as a new `alembic/versions/NNN_*.py`; never hand-edit existing migrations. When an existing DB is behind head (or stamped at an unknown revision), `database/backup.py:snapshot_database` first copies it into a sibling `db_backups/` dir via the sqlite backup API — best-effort, never blocks startup; retention `FLOWFILE_DB_BACKUP_KEEP` (default 10, `0` disables).
- **Settings are `MutableBool`** so they toggle live: `SINGLE_FILE_MODE`, `OFFLOAD_TO_WORKER`, `FEATURE_FLAG_AI`, `FLOWFILE_AI_LOG_PROMPTS[_SCRUB]`.
- **Conditional execution is a local trigger rule, never a closure.** `flowfile/util/skip_rules.py` classifies every node from its *immediate* inputs in topological order (`classify_graph` for the plan, `classify_from_inputs` per stage in `_execute_stages`) — it replaced the two blind transitive closures (`node_skipper`'s BFS, the runtime `get_all_dependent_nodes()` fan-out), which are now thin wrappers over it. **ALL** is the rule for every node (an error-ish input ⇒ `SKIPPED_ERROR`, else a deliberately-skipped input ⇒ `SKIPPED_DELIBERATE`); **ANY** is `union` **only** (`ANY_INPUT_NODE_TYPES`) — the other multi-input types address inputs positionally (`input_df_1..N`), so eliding one would silently renumber the rest. Failure never inherits ANY: a failed branch must not become "half the data written successfully". The two skip *causes* must stay distinct — error-ish (misconfiguration, failure, cancellation) blocks everything downstream as before, while **deliberate** skips originate only from gates routing a side dead and are a *successful* outcome: `NodeResult(success=True, skipped=True)` rows (`_record_deliberate_skips`) so the run stays green and `nodes_completed` still reaches `number_of_nodes`, and `_run_post_execution_callbacks` treats them as complete so a Kafka source upstream of a closed gate still commits its offsets (it only logs a warning when a gated-off *output* node is involved). Gate timing is split: **parameter**-mode conditions resolve before the run (`_evaluate_gate_conditions` → `closed_gate_handles` → `compute_execution_plan`; an unevaluatable condition is left *open* so it fails visibly at the node instead of silently picking a branch), **formula** conditions (a flowfile-formula row predicate; open iff ≥1 row matches, checked against the control input when connected else the gate's own data input, `${param}` refs resolved with the run's params) are decided in the stage loop after the gate executes (bounded `filter().head(1)` collect in `_gate_formula_matches`, folded into `closed_gate_handles`) — which is why `executor.py` gives formula gates an unconditional **always-run** decision alongside output/`run_flow` nodes: the checked data can change without any hash changing. Legacy `control_input`/`invert` gate settings migrate on load (`GateInput._migrate_legacy_shape`: source → formula; inverted parameter operators flip to their complement). Gate closure is **per output handle**: an opt-in `NodeGate.else_output` gives the gate a second exit (then=output-0 / else=output-1; `output_names` property, filter-split pattern — no NamedOutputs, both handles serve the passthrough via `get_output`'s fallback), and `closed_gate_handles: dict[gate_id, frozenset[dead handles]]` (`dead_gate_handles()` in skip_rules: open+else→{output-1}, closed+else→{output-0}, closed+no-else→BOTH so a stale else edge left by toggling the option off never leaks) replaces the old id-set; `effective_input_status` takes the edge's source handle (from `_slot_input_pairs`/`_input_output_handles`), a FAILED gate still kills every handle, and the union's `_skipped_input_ids_this_run` is (source id, handle)-keyed. Known limitation: `_input_output_handles` keys one handle per source, so both exits of one gate cannot wire into the SAME consumer (pre-existing filter-split limitation). A routed gate is itself `RUN`; only its dead-handle consumers read it as skipped. Two cache invariants make gate flips safe: (1) **a node that did not execute this run has not run** — every skipped node's `has_run_with_current_setup` / `has_completed_last_run` are cleared on both `node_stats` and `_execution_state`, or dev-mode serves the previous run's frame; (2) an ANY-rule node's **surviving-input signature** is tracked in `FlowGraph._any_input_liveness` and a change calls `invalidate_cache()`, because the node hash folds only settings + input hashes and would otherwise serve the previous run's partial concat (also from the worker's `cache_results` lookup). A gated-off union input is **dropped** — the union outputs only the surviving branches, so a dead branch's unique columns are simply absent from the output (edit-time schema prediction stays gate-blind and still shows the union of all branches); the old zero-row substitution (`FlowNode._substitute_for_skipped_input`) no longer exists. Gate-blind callers (code export, single-node fetch validation) omit `closed_gate_handles` and deliberately plan as if every gate were fully open. All three code exports (Polars, FlowFrame, project) emit gates as real if-blocks from the shared base machinery (condition atoms are signed `(gate_id, needs_open)` pairs — else-side consumers render `if not (...)`, except that adjacent blocks whose conditions are one gate's exactly-complementary singleton pair fuse into a real `if`/`else` via `_conds_are_complementary`; shared prefixes, different gates, and multi-atom sets never fuse because the else of `if P and g` is not `P and not g`) — never as `df.gate(...)` calls, which would be silently ignored by the rebuilt graph's pull-based execution; unions render as guarded list-appends — each branch appends its frame to a list under its `if` guard and the union concatenates the list, so a gated-off branch simply isn't in it — except a two-input union whose guards are exactly that complementary pair, which collapses to an `if`/`else` assignment, and the all-guarded empty-frame fallback (`if not <list>:`) is emitted only when no complementary pair proves the list non-empty (independent gates); pre-initialized empty stand-ins survive only for gated return values, which the ff/project converter wraps as `ff.FlowFrame(pl.LazyFrame(schema=...))` (`_empty_frame_schema_expr` override); the formula row-probe helper gets the underlying LazyFrame via `_gate_probe_expr` → `.data`, with the `pl` import registered eagerly in `_compute_gate_conditions` because imports serialize before the gated body renders.
- **Catalog data freshness is version-addressed, never TTL'd.** Three coordinated mechanisms keep every surface current when a Delta table changes (including out-of-band writes): (1) `FlowGraph._refresh_catalog_reader_freshness` runs at every `run_graph` start — it probes live Delta versions (`catalog/delta_utils.py::get_live_delta_version`, cloud-aware) against the fingerprint stored in `NodeExecutionState.source_version_info` and calls `FlowNode.invalidate_cache()` on drift, which bumps `_cache_epoch` → rotates the node hash → defeats both the Development-mode skip and the explicit `cache_results` worker lookup, cascading downstream (pinned `delta_version` readers are never probed — deliberate time travel; readers over non-optimized virtuals invalidate every run, like `run_flow`). (2) Viz session keys (`catalog/services/visualizations.py`) fold live versions in: `tbl:{id}:v{version}`, SQL digests include referenced-table versions, fvt keys embed the snapshot filename+mtime — a write rotates the key and the stale worker child idles out (no push-evict; the endpoint exists for ops only). (3) Virtual-table resolution: `check_source_versions_current(None)` is **fail-closed** (no fingerprint ⇒ stale ⇒ re-run the producer); `_collect_source_table_versions` is **complete-or-nothing** (any unfingerprintable source ⇒ `None`; a flow with zero catalog sources stamps `"[]"` — provably complete, keeps plan replay); callers key the worker IPC cache via `fresh_versions_hash()` **after** resolution (identity-map-bypassing `get_table_fresh`), and the worker names that cache by `(table_id, plan_bytes, versions_hash)` with `NO_VERSIONS_HASH` always rebuilding. When touching any of these, keep the invariant: a cache key must change whenever the data it names can have changed.
- **Unregistered drafts & scratch schemas:** `POST /editor/create_flow/` takes two independent switches — `persist` (write the YAML) and `register_in_catalog` (mint the `FlowRegistration` row). Quick-create sends `register_in_catalog=false`, so a draft has no `source_registration_id` — no run history, schedules or API publishing until it is filed. **First run promotes it** (`routes/routes.py`, before execution): it re-registers any unregistered flow and materialises the file when missing, so a deleted registration comes back if the flow is run again — making a deliberate deletion durable needs a tombstone (open follow-up). Drafts accrete under the app-managed scratch schemas `General > {Unnamed Flows | Python Editor}`, swept in bulk by `POST /catalog/namespaces/{id}/cleanup_flows` → `CatalogService.cleanup_scratch_namespace` (restricted server-side to those two names; enumerates through the access filter, deletes row-by-row via the gated `delete_flow`, so artifact-bearing and unmanageable rows are kept and counted as `kept`). **App-managed schemas must be `is_public=True`** — seeded ones get it in `init_db.py`, and lazily created ones (`Python Editor`, via `_ensure_general_child`) now do too, with `create_default_catalog_namespace` repairing pre-existing private rows; a private one is invisible to every user but General's owner in multi-user mode.
- **Run rows are keyed by `flow_uuid`:** `repository._runs_of_registration` resolves registration-scoped run queries (run history, `has_active_run`) through `FlowRun.flow_uuid`, so a run row with a NULL uuid is invisible to core. Every writer must stamp it — including the scheduler, whose `shared.models.FlowRun` mapping now carries `flow_uuid` and copies it from the registration in `_maybe_launch`. Runs whose subprocess died are closed by `shared.run_completion.reap_orphaned_runs()`, called best-effort in the core lifespan (before the embedded scheduler starts, so the two reaps never overlap on SQLite) and on every scheduler tick; it never touches `in_designer_run` rows, which are pid-less by nature.
- **Project git-tracking** (`project/`, router `routes/project.py`, the `*project*` migrations in `alembic/versions/`, `FLOWFILE_ENABLE_PROJECTS`): mirrors an install's flows/connections/schedules/catalog into a deterministic, secret-free git folder. The **DB stays the runtime source of truth**: projection (`projection.py`, DB→files) runs automatically as fire-and-forget hooks at the tail of catalog/secret/connection/flow save paths, and import (`importer.py`, files→DB) runs only at explicit boundaries (open/restore/reload). **The projection hooks must never raise** — failures are swallowed (logged) so a sync error never breaks the originating save. In docker mode the router 404s unless `FLOWFILE_ENABLE_PROJECTS` is set, and projects are confined to `<user_data>/projects/<owner_id>`.

## Gotchas
- `flowfile_core/__init__.py` runs `validate_setup()` then `init_db()` **on import** — importing the package has side effects (DB file creation, Alembic schema migration, default-user seeding).
- Don't bypass the worker offload for full datasets, and don't add eager litellm imports anywhere under `ai/` — both break invariants enforced by tests.
- There is no package-level `pyproject.toml`; deps, scripts, ruff, and pytest config all live in the monorepo-root `pyproject.toml`. The local `.env` is read by `settings.py` via Starlette `Config`.
- Kernel / AI-local-model / Docker features need Docker available; absence surfaces as runtime errors, not import errors.
- **`FLOWFILE_SECURE_STORAGE_PATH` relocates the electron `SecureStorage` dir** (`jwt_secret` / `master_key` / `internal_token`). Set by `tests/conftest.py` and `flowfile_frame/tests/conftest.py` before any core import (`_storage = SecureStorage()` runs at `auth/secrets.py` import) so suites don't write into the developer's real `~/.config/flowfile`. **`flowfile_worker` honors the same var** (`flowfile_worker/secrets.py`) — it must, because core encrypts `$ffsec$` secrets with the master key in that dir and the worker re-derives it independently; a split store makes every worker-offloaded secret decrypt fail ("Task failed"). So a worker started by hand in another shell needs the var exported too, or core's suite (which reuses an already-running worker) will diverge from it. The electron `internal_token` is persisted there so CLI subprocess runs (manual + scheduled) present the same kernel→core token as the server.
- **Community-node installs are admin-gated** (`require_admin`, same reasoning as custom-node mounts — they land executable code install-wide) and tracked by a `community_receipts.json` sidecar living **inside** `user_defined_nodes/` next to the flat `<id>.py` files (never touch non-community files on uninstall). Consent + the client's sha256 pins are advisory; `installer.py` re-scans downloaded bytes and is authoritative — it also refuses blocklisted ids (410), yanked versions (410 `YANKED`), and `min_flowfile_version` mismatches (409 `INCOMPATIBLE_VERSION`); install never execs the node module (lazy exec at placement via `registry.ensure_class`). For offline/local UI work set `FLOWFILE_COMMUNITY_INDEX_URL` to a local `index.json` path (**fixture mode** — no GitHub repo needed).
- **In-app PR publishing must never surface a GitHub-domain failure as HTTP 401** — the frontend axios interceptor treats 401 as JWT expiry and would trigger a refresh/logout. `community_github.py` / `publish-pr` map GitHub errors to typed `error_code` payloads on non-401 codes instead (412 `GITHUB_NOT_CONNECTED`/`GITHUB_TOKEN_INVALID`, 410 `DEVICE_EXPIRED`/`DEVICE_DENIED`, 502 `GITHUB_API_ERROR`/`GITHUB_RATE_LIMITED`, 503 `GITHUB_NOT_CONFIGURED`, 409 `VERSION_NOT_INCREMENTED`). The device-flow client id comes from `settings.get_community_github_client_id` (env var → `.env` → baked `COMMUNITY_GITHUB_CLIENT_ID_DEFAULT`, so non-empty by default; an empty resolution ⇒ device flow disabled, PAT + bundle still work).
