# CLAUDE.md - flowfile_frontend

Tauri 2 desktop shell + Vue 3 renderer: the VueFlow-based visual flow designer and all of Flowfile's UI (designer, AI assistant, catalog, connections, admin, dashboards). Package-specific notes; see the root `/CLAUDE.md` for monorepo-wide setup, build, lint, ports, and cross-package contracts.

## Role
Pure client. Talks to `flowfile_core` over HTTP; never to `flowfile_worker` directly. Two run modes:
- **web** (`vite`, dev port 8080): renderer only. API calls go to `<origin>/api/*`; the Vite dev proxy (or nginx in Docker, see `nginx.conf`) rewrites `/api/` → core:63578, including replicating FastAPI's absolute-307 trailing-slash redirects (`vite.config.mjs` `proxy.configure`).
- **desktop** (`tauri dev`): Rust shell in `src-tauri/` spawns the two Python services as **sidecars** on a discovered free `(core, worker)` port pair (scan starts at 63578, `core = 63578 + k*2`, `worker = core+1`), injects them into `window.__FLOWFILE_PORTS__` before any renderer script runs; the renderer then hits `http://127.0.0.1:<core>/` directly (no `/api` prefix).
- Axios baseURL is resolved once in `src/renderer/config/constants.ts` (`flowfileCorebaseURL`). Desktop runtime detected via `window.__TAURI_INTERNALS__` (`isDesktop` in `lib/desktop.ts`).

## Layout
- `src/renderer/main.ts` — Vue bootstrap (createApp, router, i18n, Element Plus, theme + auth init). Vite `root` is `src/renderer/`, entry `index.html`.
- `src/renderer/app/` — all renderer code; the `@` alias points here.
- `src/renderer/app/views/<Name>View/` — one dir per routed page (DesignerView, CatalogView, ConnectionsView, AdminView, LoginView, SetupView, ComputeView, AiProvidersView, …). `app/pages/NodeDesigner.vue` is a standalone routed page outside `views/`. ComputeView is the two-tab Compute page (catalog-style `?tab=` sidebar children): it mounts `KernelManagerView` (still its own dir, no longer routed directly) as the Python Kernels tab and `PerformancePanel` + `components/settings/WorkerPoolCard.vue` as the admin-only Performance tab — the sole home of the warm-worker-pool dashboard; the legacy `kernelManager` route redirects to `compute?tab=kernels`.
- `src/renderer/app/pages/nodeDesigner/` — the Node Designer: `designerState.ts` is a 1:1 TS mirror of core's `node_designer/state.py` (the wire contract — the frontend edits `DesignerState` and **never generates Python**; save/preview/dry-run go through `api/nodeDesigner.ts`, backend renders the `.py`). `designer/` holds the page components (MetadataPanel with category combobox, WorkspaceTabs Form|Code|Test, FormCanvas WYSIWYG hosting the shared `customNode/CustomNodeForm.vue` in editMode, ControlInspector, ExecutionEnvironmentPicker, FormFieldsOverview, testPanel/). **Reordering lives entirely in `FormCanvas.vue`'s slots** — `CustomNodeForm.vue` is shared with the runtime node drawer and must never gain drag attributes of its own. Groups reorder by dragging a header or by its ▲/▼ buttons (`store.moveSection`); dropping on a header lands the dragged group at that header's position and the row under the last group is the only drop target that lands at the end. Dragging a control's grip onto another group's header, or the ControlInspector's **Group** select, calls `store.moveComponentToSection`, which renames on name collision and retargets every dotted `visible_when` reference through both the move and the rename. Section order needs no ordinal field: it round-trips through `codegen.py` (class-body order) and `parsing.py` (AST source order). State in `stores/node-designer-store.ts` (per-node localStorage drafts, dirty guards, body-only `processBody` under a read-only signature header; same pattern for the optional `predictSchemaBody`/`predictSchemaEnabled` backing the Code tab's collapsible "Schema prediction" editor → `DesignerState.predict_schema_code`). Custom-node icons are JWT-gated — always resolve via `app/composables/useCustomNodeIcon.ts` (authed blob), never raw `<img src>` endpoint URLs. The Catalog's Custom Nodes tab (`views/CatalogView/CustomNodesPanel.vue`) deep-links here via `?openFile=`. The designer's **Publish** button (`designer/DesignerHeader.vue`) opens `pages/nodeDesigner/PublishBundleModal.vue` — readiness checklist, a version banner (published vs publishing, one-click semver bumps that persist via `saveNode` before re-checking), license/screenshot upload plus optional README/changelog textareas (the README persists via the `/community_nodes/readme/{stem}` sidecar — loaded on open, debounce-saved, registry-prefilled for receipt-tracked installs only; an **Insert template** button drops in the standard sections), in-app **Publish on GitHub** card, and blob-download of the community bundle as the no-account fallback (all via `/community_nodes/*`). `NodeDesigner.vue` `handlePublish` auto-saves dirty state before opening so on-disk metadata matches the checklist. The GitHub card has three connect states — not-connected (device flow: big `user_code` + copy + open github.com/login/device via `desktop.openExternal`, plus a collapsed PAT-paste fallback) → connected (`@login` chip + an open-PR note fetched via `GET /community_nodes/publish-pr/open` + confirmation checkbox gating **Create pull request**) → PR success (link + "what happens next" + an **Update pull request** button that clears `prResult` back to the connected state, keeping `confirmed` ticked; re-publishing the same version refreshes the open PR, status `updated`) — with a `fork_creating` retry loop. Its pure logic lives in `pages/nodeDesigner/publishGithub.ts` (error-code→copy map, `nextPollDelayMs` device-poll cadence, fork-retry budget, `canCreatePr`; no Vue/axios imports → plain vitest `publishGithub.test.ts`); typed `PublishPrBlockedError` in `api/nodeDesigner.ts`. **Poll/fork timers are cleared on unmount and on modal close** (`stopGithubTimers`), and GitHub errors surface via typed non-401 codes (a 401 would trip the axios JWT-refresh interceptor). **The modal never unmounts** (`NodeDesigner.vue` passes a plain `:show` prop), so opening it for another node is its only "mount": a `hydrating` flag covers that window and a `loadSeq` token invalidates in-flight responses from the node you switched away from. Every watcher that persists or re-checks must be gated on `hydrating`, **not** on `props.show` — `handlePublish` sets `fileName` and `show` in one tick, so `show` is already true while the reset runs, and an ungated reset armed a debounced `PUT {readme: ""}` that tombstoned the incoming node's sidecar. The `fileName` watcher owns the per-node reset (readme, changelog, version, issues, description, license, category, repository, screenshots + `revokeUrls`); `resetGithubTransient` owns the rest on close — don't duplicate fields across the two.
- **Community Nodes catalog tab** (`views/CatalogView/`): the `community` tab in `catalogTabs.ts` renders `CommunityNodesPanel.vue` (card grid, filters, install-state footer, and a warning banner from the `/index` `alerts` field for installed nodes the registry later blocked/yanked), `CommunityNodeDetailModal.vue` (README + screenshot lightbox), and `CommunityConsentDialog.vue` (capability chips + risk copy + required acknowledge checkbox before install). Store: `stores/community-nodes-store.ts`; typed axios wrappers in `api/communityNodes.ts` (no trailing slashes; typed 400/409/502/503 errors); capability-chip copy in `communityCapabilities.ts`. **Community media (icons/screenshots) must go through core** — the Tauri CSP forbids GitHub/CDN URLs and the endpoints are JWT-gated, so resolve every asset via `composables/useCommunityMedia.ts` (authed blob → object URL, clone of `useCustomNodeIcon.ts`); never a raw `<img src>` endpoint URL, CDN URL, or inline SVG.
- `src/renderer/app/components/kernel/` — shared kernel UI: `KernelCreateForm.vue` (the extracted create form; `views/KernelManagerView/CreateKernelForm.vue` is now a thin collapsible-card wrapper around it), `CreateKernelDialog.vue` (el-dialog seeded from a backend `KernelSuggestion.config`, create→auto-start→`created` emit), `NodeKernelSetupDialog.vue` (post-community-install kernel setup), and pure `kernelMatch.ts` / `kernelActions.ts` (match badges/sort/auto-select; stop→PATCH→start package upgrades — both vitest-covered). Composables: `useKernelResources.ts` (module-singleton docker-status + flavour cache), `useKernelMatch.ts` (per-instance `POST /kernels/match` state with stale-response guards), and `useKernelReadiness.ts` (module-singleton `POST /kernels/match/batch` digest cache for list-view badges — Catalog → Custom Nodes rows and the palette's `NodeListItem` kernel-badge tint). The custom-node drawer (`customNode/CustomNode.vue`) and the designer Test tab (`testPanel/TestPanel.vue` + `useDryRunTest.ts`, live-deps debounced re-match) rank kernels by dependency match, auto-preselect a full match when nothing is persisted, and offer "Create kernel for this node" / "Add missing packages".
- `src/renderer/app/features/designer/` — flow editor internals (`drawflowExtensions.ts`, `editor/` with FunctionEditor / ColumnSelector / pythonEditor).
- `src/renderer/app/features/ai/` — AI assistant, command palette, ghost-node suggestions, diff panel.
- `src/renderer/app/components/tutorial/` — interactive Getting Started tour. Event-driven: app seams (`useDragAndDrop.onDrop`, Canvas `onConnect`/`openNodeSettings`/node-remove, HeaderButtons create/save, `useFlowExecution` run start/complete) call `tutorialStore.notify(event)`; steps declare `advanceWhen`/`isSatisfied` and auto-skip when already done. Pure logic in `tutorial-engine.ts` (node-env unit tests), cross-store watchers in `useTutorialBridge.ts`; a 1s resync (`resyncFromApp`) re-derives node/edge context from the live canvas so uninstrumented mutations (undo, paste, flow reload) can't desync the tour. Never re-add step-id `setTimeout` advance hacks in components — `notify()` is the single advance path. localStorage keys: `flowfile-tutorial-completed`, `flowfile-tutorial-dismissed`, `flowfile-tutorial-banner-dismissed`. E2E: `tests/tutorial.spec.ts`.
- `src/renderer/app/components/nodes/` — VueFlow node wrappers; `node-types/elements/` has one subdir per node type (dozens of `.vue` settings components). `GenericNode.vue` and `composables/useDragAndDrop.ts` resolve them via `import.meta.glob` + a string-interpolated path. `getComponents.ts` is unrelated — it lazy-loads only `elements/manualInput/*.vue` editor cells.
- `src/renderer/app/stores/` — Pinia stores (`flow-store`, `node-store`, `results-store`, `auth-store`, `theme-store`, the `ai-*` stores, …); `index.ts` is the plugin.
- `src/renderer/app/api/` & `app/services/` — Axios API wrappers; `services/` adds auth/setup/user services, `axios.config.ts` (interceptors, `withCredentials`), and SSE clients (`aiStreamClient.ts`, `aiDiffClient.ts`).
- `src/renderer/app/composables/`, `app/router/index.ts`, `app/i18n/` (only locale `locales/gb.json`), `app/layouts/`.
- `src/renderer/lib/desktop.ts` — the only renderer↔Tauri bridge (invoke/listen wrappers + web-mode fallbacks).
- `src/renderer/config/` — `constants.ts` (baseURL/port resolution), `environment.ts` (NODE_ENV-derived `ENV` flags).
- `src-tauri/src/` — Rust shell: `lib.rs` (entry, `generate_handler!`, lifecycle), `commands.rs`, `sidecar/` (`mod.rs` spawn + port scan, `readiness.rs`, `shutdown.rs`), `menu.rs`, `oauth.rs`, `window.rs`, `state.rs`, `env.rs`.

## Key patterns & conventions
- Path aliases declared in **three** places, keep in sync: `vite.config.mjs` and `tsconfig.json` define `@` (`@/*` glob form in tsconfig) plus `@/api`, `@/types`, `@/stores`, `@/composables`; `vitest.config.ts` defines only bare `@`.
- Router uses **hash history** (`createWebHashHistory`). Routes are lazy `import()`ed; most live under the `/main` `AppLayout` parent with `meta.requiresAuth` (default true). A `router.onError` guard in `router/index.ts` catches chunk-load failures (dev: stale Vite optimize-dep 504s; prod: a chunk a redeploy removed) and reloads **once per target** via a `flowfile:chunk-reload` sessionStorage key, then shows an error instead of looping — don't remove the once-per-target dedupe.
- All desktop-native calls MUST go through `lib/desktop.ts`, which no-ops / falls back in web mode (`isDesktop` guard). Don't import `@tauri-apps/*` directly in view code. New Tauri commands must be registered in `src-tauri/src/lib.rs` `generate_handler!` (the authoritative command list) and wrapped in `desktop.ts`. `desktop.ts` also calls plugin commands directly (`plugin:opener|open_url`, clipboard-manager) — no Rust command needed for those.
- No JSX/TSX: React (`react`/`react-dom` v19, pinned via `overrides`) is only a dynamic `import("react")` inside the `@kanaries/graphic-walker` Vue wrappers. `vite.config.mjs` deliberately omits `@vitejs/plugin-react`; `tsconfig.json` excludes `*.tsx`/`*.jsx`.
- AG Grid is the **modular** `@ag-grid-community/*` v31 (`ModuleRegistry.registerModules`; not the monolithic `ag-grid-community`).
- OAuth: the GA connection opens the **system browser** (`desktop.openExternal`) because Google blocks embedded webviews; the generic `open_oauth` command opens a modal Tauri webview window (`oauth.rs`) for providers that allow it.
- **Docs links go through `app/lib/docsLinks.ts`** (`DOCS_BASE_URL` + `docsUrl(path)`), mirrored by `src-tauri/src/menu.rs` `DOCS_URL` — change both together. Paths must carry the `.html` extension (mkdocs runs `use_directory_urls: false`, so a trailing-slash URL 404s). In-app docs always open in the **system browser** via `desktop.openExternal`; never iframe the docs site — the Tauri CSP only allows `frame-src 'self' https://accounts.google.com`, which is why the old `DocumentationView` rendered blank on desktop and was removed. Per-node "Read more" targets resolve through `views/DesignerView/nodeDocsLinks.ts`, a hand-authored `item` → `page.html#anchor` map: **do not derive the page from `node_group`** (`window_functions` and `wait_for` are documented on pages that disagree with their palette group).
- **Catalog save-target pickers must use `composables/useWritableNamespaces.ts`** (`writableSchemaNamespaces` for store-tree dropdowns, `writableSchemaOptions`/`pruneNonWritable` for self-fetched trees, `isWritableNamespace` for tree rows): it strips system schemas and read-only (`use`-grant) namespaces so users are never offered a save target the backend will 403. Read pickers (catalog reader, apply-model, run-flow, open dialogs) must NOT be filtered this way. Catalog write failures toast via `catalogSaveErrorMessage` (`composables/saveError.ts`), which maps 403 to a friendly read-only message.
- **Canvas handle labels**: a node with >1 handle on a side gets a compact letter plus the declared name as the handle's native tooltip, derived in `utils/nodeHandles.ts` and rendered by `NodeWrapper.vue` (the only component with *labeled* `<Handle>`s — `GroupNode.vue` renders a plain unlabeled pair). `outputHandle.ts::handleLetters` prefers each name's **initial** (join → L/R, filter split → P/F, gate else output → T/E) and falls back to positional A/B/C for the whole side when a name is missing, doesn't start alphanumeric, or two initials would collide — a duplicated letter is worse than an arbitrary one. Two distinct backend fields feed this and must not be conflated: `NodeTemplate.input_labels` is the **static, display-only** per-type list (join → `["Left","Right"]`, custom nodes via `CustomNodeBase.input_labels`), while `NodeInput.input_names` is the **per-instance dynamic-handle** list for `run_flow` only — and `deriveHandles` branches on the latter, so putting static names in `input_names` turns index 0 into a bottom parameter handle and silently drops an input. For a STATIC node that wants a bottom "parameter" pip (gate's control input), use the cosmetic `NodeTemplate.control_input_indices` instead — `buildInputHandles` renders marked indices as `kind: "parameter"`/`Position.Bottom` and `NodeWrapper.vue` already dispatches on `kind`; note the remaining lone side input then loses its letter chip (sideInputs.length rule) by design. VueFlow's `<Handle>` drops fallthrough attrs, so the tooltip is applied with the local `v-native-title` directive, never a plain `:title` (and never on `.handle-label`, which is `pointer-events: none`).
- Canvas node warning dots (amber) are backend-fed: flow open / settings save / connect / delete / run-completion call `flow-store.fetchSettingsValidation` → `GET /flow/settings_validation` → `results-store.applySettingsValidation`, which owns only entries marked `source: "backend"` and replaces them wholesale per flow. Drawer config checks (WindowFunctions/Unique/GroupBy) still write unmarked entries via `setNodeValidation`. Never re-add per-node downstream validate-func registries — the old client-side missing-column checks were removed in favor of the backend feed.
- Canvas overlay panels (`components/common/DraggableItem/`) persist **user intent only** (dock side + per-axis size/offset/gap, localStorage `overlayPositionAndSize.v4_*`), written solely at gesture end via `stateStore.commitIntent`; the on-screen rect is derived per frame by the pure `layoutGeometry.computeLayout(intent, config, containerBounds, minimized)` against the single shared container measurement `Canvas.vue` registers. **Never persist derived geometry** — that split is the fix for the historical drawer-collapse corruption (150×100 panels). Docked panels resize via splitter edges, pop out only past a 48px deliberate drag, and snap back into a dock when released within 40px of an edge.

## Running / entry points
From this dir (`npm install` first):
- `npm run dev:web` — renderer at :8080 (needs `poetry run flowfile_core` running for `/api`).
- `npm run dev` — full Tauri desktop; runs `npm run dev:web` as `beforeDevCommand`, then the shell spawns sidecars (requires staged sidecar binaries via `make build_python_services && make rename_sidecars` from repo root — see root doc).
- `npm run build:web` — `npm run lint` + `vue-tsc --noEmit` + Vite build → `build/renderer/`.
- `npm run build` — same checks + `tauri build`. `tauri.conf.json`: `devUrl http://localhost:8080`, `frontendDist ../build/renderer`, `beforeDevCommand npm run dev:web`, `beforeBuildCommand npm run build:renderer-only`.

## Testing
- **Unit (Vitest):** `npm run test:unit` (`vitest.config.ts`, `node` env, `globals:false`). Picks up only `src/**/*.test.ts` (stores, composables, per-node logic, view helpers). Co-locate new unit tests next to the module.
- **E2E (Playwright):** `tests/*.spec.ts` (`web-flow.spec.ts`, `canvas-overlays.spec.ts`). `npm run test:web` runs the web-flow spec; `npm run test:all` runs the dir. Needs core (`:63578`) + the web server running first. `playwright.config.ts`: single worker, 120s timeout. `make test_e2e` from repo root orchestrates it.

## Gotchas
- `vite.config.mjs` sets `server.strictPort: true` — the dev server fails (not falls back) if 8080 is taken, on purpose so Tauri's hard-coded `devUrl` never points at the wrong port. Dep pre-bundling relies on Vite's own hash-based invalidation; `optimizeDeps.force: true` was **removed** because it deletes the shared `node_modules/.vite/deps` on every start (including a start that then dies on strictPort), leaving a still-running server serving "504 (Outdated Optimize Dep)" for every not-yet-fetched dep. Use `npm run dev:web:force` to rebuild the cache deliberately.
- ESLint here is the **legacy** `.eslintrc.js` (eslint 8 + `vue-eslint-parser`), not the root flat config. `npm run lint` only touches `src/**/*.{ts,vue}` (with `--fix`).
- Sidecar shutdown is a graceful ladder (HTTP `/shutdown` → SIGTERM → SIGKILL) in `src-tauri/src/sidecar/shutdown.rs`; sidecars also self-reap via `FLOWFILE_SUPERVISOR_PID` (set in `env.rs`) + `shared/parent_watcher.py` if the shell is hard-killed. macOS Cmd+Q/dock quit fires `RunEvent::Exit` (not `ExitRequested`), so `lib.rs` matches both. Desktop E2E for this path is a known gap (TODO at top of `tests/web-flow.spec.ts`).
- `lib.rs` builds the main window with `.disable_drag_drop_handler()`, so there is no `tauri://drag-drop` event: OS file drops land in the renderer as ordinary HTML5 `drop` events alongside the internal palette/grid drags. **`text/uri-list` is empty for OS file drops in WKWebView too** — WebKit blanks `file://` URLs out of `DataTransfer` (only http/https/data/blob survive), so no webview hands the renderer a real path. Each desktop platform recovers them differently: **macOS** reads the drag pasteboard (`read_drag_paths` command, `src-tauri/src/drag_paths.rs` → `desktop.readDragPaths()`, prefetched at drag-enter while the drag session is live); **Windows** hands the dropped `File` objects back to the shell via WebView2's `postMessageWithAdditionalObjects` and reads `ICoreWebView2File::Path` off each (`src-tauri/src/webview2_drop.rs` → `desktop.requestDroppedFilePaths()`, answered on the `file-drop-paths` event); **WebKitGTK** has no source at all and falls back to copying the `File` up to core. `desktop.canLinkDroppedFiles` is the renderer-side "can this platform link" flag (dropEffect, overlay hint). Every branch still decides via the single pure resolver `app/utils/fileDropStrategy.ts::resolveDropStrategy` (uri-list first, then native paths, paired by basename) — put new drop rules there, not in the drop handler. Windows note: wry's IPC handler sees our correlation message too and forwards it to tauri, which fails to parse it as JSON and evals one `console.error` in the devtools console per drop — harmless, and deliberately chosen over shapes that reach tauri's invoke-key check (that one `eprintln!`s to the log).
- The per-node settings loader is a **string-interpolated dynamic import** keyed by node-type folder (`GenericNode.vue`, `useDragAndDrop.ts`): renaming a node's settings dir/component breaks loading at runtime (logs `console.error`, no build error).
- **Canvas clipboard & hotkeys are centralized.** All canvas copy/paste flows through `app/composables/useFlowClipboard.ts` (sole owner of the node-copy buffer in localStorage, the `Flowfile nodes · N · <uuid>` clipboard sentinel, and the `isCanvasClipboardTarget` panel denylist) and all canvas shortcuts through `app/composables/useFlowHotkeys.ts` — never add another `document`/`window` clipboard or canvas-keydown listener. Cmd+C/V must stay **ClipboardEvent-based, not keydown**: the Tauri Edit-menu accelerators (`src-tauri/src/menu.rs`) consume the keystroke on macOS but still emit DOM ClipboardEvents. A node paste happens ONLY when the pasted text matches the buffer's sentinel uuid (generic paste) or via the context menu's explicit "Paste Node" action, which deliberately does **no clipboard read** (web Firefox/insecure contexts can't read outside a paste event). Clipboard events targeting `<body>` are classified by the last pointerdown target — non-focusable panel chrome (labels, resizers, WebKit buttons) never takes focus, so the event target alone can't distinguish panel from canvas. An active text selection defers **copy** (only) to the native text copy — the canvas renders selectable text (node-description `<pre>`s) outside any editable element, so `hasTextSelection` is a separate copy-path guard, deliberately not folded into the target predicate (a stray selection must never suppress paste). Every floating panel roots at `DraggableItem`, whose root carries `data-canvas-overlay` — the attribute the denylist keys on; a new overlay component not built on DraggableItem must add it itself.
