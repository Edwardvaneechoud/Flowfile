# CLAUDE.md - flowfile_frontend

Tauri 2 desktop shell + Vue 3 renderer: the VueFlow-based visual flow designer and all of Flowfile's UI (designer, AI assistant, catalog, connections, admin, dashboards). Package-specific notes; see the root `/CLAUDE.md` for monorepo-wide setup, build, lint, ports, and cross-package contracts.

## Role
Pure client. Talks to `flowfile_core` over HTTP; never to `flowfile_worker` directly. Two run modes:
- **web** (`vite`, dev port 8080): renderer only. API calls go to `<origin>/api/*`; the Vite dev proxy (or nginx in Docker, see `nginx.conf`) rewrites `/api/` → core:63578, including replicating FastAPI's absolute-307 trailing-slash redirects (`vite.config.mjs` `proxy.configure`).
- **desktop** (`tauri dev`): Rust shell in `src-tauri/` spawns the two Python services as **sidecars** on a discovered free `(core, worker)` port pair (scan starts at 63578, `core = 63578 + k*2`, `worker = core+1`), injects them into `window.__FLOWFILE_PORTS__` before any renderer script runs; the renderer then hits `http://127.0.0.1:<core>/` directly (no `/api` prefix).
- Axios baseURL is resolved once in `src/renderer/config/constants.ts` (`flowfileCorebaseURL`). Desktop runtime detected via `window.__TAURI_INTERNALS__` (`isDesktop` in `lib/desktop.ts`).

## Layout

- `src/renderer/app/` — all renderer code; the `@` alias points here.
- `src/renderer/app/components/layout/Sidebar/` — the rail is organised by intent, not subsystem: Home, Designer, **Catalog** (browse, analyze and operate tabs) and **Settings** (connections, compute tabs, extensions incl. node designer + the catalog's extend tabs, and the workspace/admin pages) — `NavigationRoutes.ts` is the table, `MenuAccordion.vue` renders it. The extend tabs still render inside CatalogView, whose tab bar only shows the `CatalogSection` (`catalogTabs.ts`) its active tab belongs to. Route names and paths are unchanged; the footer folds theme, sign-out, tutorial, docs and privacy into one "Help & more" menu.

ComputeView is the two-tab Compute page (catalog-style `?tab=` sidebar children): it mounts `KernelManagerView` (still its own dir, no longer routed directly) as the Python Kernels tab and `PerformancePanel` + `components/settings/WorkerPoolCard.vue` as the admin-only Performance tab — the sole home of the warm-worker-pool dashboard; the legacy `kernelManager` route redirects to `compute?tab=kernels`. **AiSettingsView** is the tabbed Settings → AI page on the same pattern (`aiSettingsTabs.ts` → Providers / Assistant, with `AI_SETTINGS_TAB_ALIASES` keeping the retired `?tab=local` deep link alive; the sidebar's AI group is generated from it; both tabbed pages share `components/settings/SettingsTabBar.vue`). The on-device llama.cpp model is **a row in the Providers list**, not its own tab (`OnDeviceProviderRow.vue`: status badge, Set up / Start / Stop, and a Manage expander with a plain-language what-it-can't-do note, the model catalog and the context window) — it is a provider, the same "On-device AI" the model pickers offer. It is the only home of AI *preferences*: provider/model, the cheaper simple-task tier, agent variant and verify-plan-completion are **device-wide** (localStorage `flowfile.ai.settings.v1`, `ai-store-persistence.ts`), never per-flow — the per-flow `flowfile.ai.chat.v1.<id>` blob holds only the chat trail (legacy settings fields in it are read once for migration, never written). The chat drawer's gear popover is a quick switcher for that same provider/model plus an "All AI settings" link; the on-device install, agent variant and verification controls live only on the page. The local model cannot tool-call, so the chat hides Auto-agent/Agent for it and shows an "On-device · chat & simple build" chip beside the mode select; keep that limitation stated in plain words wherever local is offered. `aiStore.aiDisabled` is the single 503 flag every AI surface reads and `aiStore.modelsForProvider` the single model-list rule (curated ∪ default). The legacy `aiProviders` route and `connections?tab=ai` redirect to `ai?tab=providers`; the api/type modules (`api.ts`, `localModelApi.ts`, `aiProviderTypes.ts`) still live in `views/AiSettingsView/`.
- `src/renderer/app/pages/nodeDesigner/` — the Node Designer: `designerState.ts` is a 1:1 TS mirror of core's `node_designer/state.py` (the wire contract — the frontend edits `DesignerState` and **never generates Python**; save/preview/dry-run go through `api/nodeDesigner.ts`, backend renders the `.py`). `designer/` holds the page components (MetadataPanel with category combobox, WorkspaceTabs Form|Code|Test, FormCanvas WYSIWYG hosting the shared `customNode/CustomNodeForm.vue` in editMode, ControlInspector, ExecutionEnvironmentPicker, FormFieldsOverview, testPanel/). **Reordering lives entirely in `FormCanvas.vue`'s slots** — `CustomNodeForm.vue` is shared with the runtime node drawer and must never gain drag attributes of its own. Groups reorder by dragging a header or by its ▲/▼ buttons (`store.moveSection`); dropping on a header lands the dragged group at that header's position and the row under the last group is the only drop target that lands at the end. Dragging a control's grip onto another group's header, or the ControlInspector's **Group** select, calls `store.moveComponentToSection`, which renames on name collision and retargets every dotted `visible_when` reference through both the move and the rename. Section order needs no ordinal field: it round-trips through `codegen.py` (class-body order) and `parsing.py` (AST source order). State in `stores/node-designer-store.ts` (per-node localStorage drafts, dirty guards, body-only `processBody` under a read-only signature header; same pattern for the optional `predictSchemaBody`/`predictSchemaEnabled` backing the Code tab's collapsible "Schema prediction" editor → `DesignerState.predict_schema_code`). Custom-node icons are JWT-gated — always resolve via `app/composables/useCustomNodeIcon.ts` (authed blob), never raw `<img src>` endpoint URLs. The Catalog's Custom Nodes tab (`views/CatalogView/CustomNodesPanel.vue`) deep-links here via `?openFile=`. The designer's **Publish** button (`designer/DesignerHeader.vue`) opens `pages/nodeDesigner/PublishBundleModal.vue` — readiness checklist, a version banner (published vs publishing, one-click semver bumps that persist via `saveNode` before re-checking), license/screenshot upload plus optional README/changelog textareas (the README persists via the `/community_nodes/readme/{stem}` sidecar — loaded on open, debounce-saved, registry-prefilled for receipt-tracked installs only; an **Insert template** button drops in the standard sections), in-app **Publish on GitHub** card, and blob-download of the community bundle as the no-account fallback (all via `/community_nodes/*`). `NodeDesigner.vue` `handlePublish` auto-saves dirty state before opening so on-disk metadata matches the checklist. The GitHub card has three connect states — not-connected (device flow: big `user_code` + copy + open github.com/login/device via `desktop.openExternal`, plus a collapsed PAT-paste fallback) → connected (`@login` chip + an open-PR note fetched via `GET /community_nodes/publish-pr/open` + confirmation checkbox gating **Create pull request**) → PR success (link + "what happens next" + an **Update pull request** button that clears `prResult` back to the connected state, keeping `confirmed` ticked; re-publishing the same version refreshes the open PR, status `updated`) — with a `fork_creating` retry loop. Its pure logic lives in `pages/nodeDesigner/publishGithub.ts` (error-code→copy map, `nextPollDelayMs` device-poll cadence, fork-retry budget, `canCreatePr`; no Vue/axios imports → plain vitest `publishGithub.test.ts`); typed `PublishPrBlockedError` in `api/nodeDesigner.ts`. **Poll/fork timers are cleared on unmount and on modal close** (`stopGithubTimers`), and GitHub errors surface via typed non-401 codes (a 401 would trip the axios JWT-refresh interceptor). **The modal never unmounts** (`NodeDesigner.vue` passes a plain `:show` prop), so opening it for another node is its only "mount": a `hydrating` flag covers that window and a `loadSeq` token invalidates in-flight responses from the node you switched away from. Every watcher that persists or re-checks must be gated on `hydrating`, **not** on `props.show` — `handlePublish` sets `fileName` and `show` in one tick, so `show` is already true while the reset runs, and an ungated reset armed a debounced `PUT {readme: ""}` that tombstoned the incoming node's sidecar. The `fileName` watcher owns the per-node reset (readme, changelog, version, issues, description, license, category, repository, screenshots + `revokeUrls`); `resetGithubTransient` owns the rest on close — don't duplicate fields across the two.
- **Community Nodes catalog tab** (`views/CatalogView/`): the `community` tab in `catalogTabs.ts` renders `CommunityNodesPanel.vue` (card grid, filters, install-state footer, and a warning banner from the `/index` `alerts` field for installed nodes the registry later blocked/yanked), `CommunityNodeDetailModal.vue` (README + screenshot lightbox), and `CommunityConsentDialog.vue` (capability chips + risk copy + required acknowledge checkbox before install). Store: `stores/community-nodes-store.ts`; typed axios wrappers in `api/communityNodes.ts` (no trailing slashes; typed 400/409/502/503 errors); capability-chip copy in `communityCapabilities.ts`. **Community media (icons/screenshots) must go through core** — the Tauri CSP forbids GitHub/CDN URLs and the endpoints are JWT-gated, so resolve every asset via `composables/useCommunityMedia.ts` (authed blob → object URL, clone of `useCustomNodeIcon.ts`); never a raw `<img src>` endpoint URL, CDN URL, or inline SVG.
- `src/renderer/app/components/kernel/` — shared kernel UI: `KernelCreateForm.vue` (the extracted create form; `views/KernelManagerView/CreateKernelForm.vue` is now a thin collapsible-card wrapper around it), `CreateKernelDialog.vue` (el-dialog seeded from a backend `KernelSuggestion.config`, create→auto-start→`created` emit), `NodeKernelSetupDialog.vue` (post-community-install kernel setup), and pure `kernelMatch.ts` / `kernelActions.ts` (match badges/sort/auto-select; stop→PATCH→start package upgrades — both vitest-covered). Composables: `useKernelResources.ts` (module-singleton docker-status + flavour cache), `useKernelMatch.ts` (per-instance `POST /kernels/match` state with stale-response guards), and `useKernelReadiness.ts` (module-singleton `POST /kernels/match/batch` digest cache for list-view badges — Catalog → Custom Nodes rows and the palette's `NodeListItem` kernel-badge tint). The custom-node drawer (`customNode/CustomNode.vue`) and the designer Test tab (`testPanel/TestPanel.vue` + `useDryRunTest.ts`, live-deps debounced re-match) rank kernels by dependency match, auto-preselect a full match when nothing is persisted, and offer "Create kernel for this node" / "Add missing packages".
- Catalog header tab bar (`views/CatalogView/CatalogView.vue`): tabs come from `catalogTabs.ts`; a persisted **compact mode** (`flowfile-catalog-tabs-compact`, toggle at the bar's right end, same localStorage pattern as the tree collapse) folds every label but the active tab's while keeping the section captions and dividers; tabs are chunked per section (`tabGroups`) so hovering a section unfolds its labels. Keep compact and expanded heights close so toggling doesn't jump the content.
- Dashboards (`views/DashboardsView/`) are catalog pages: the `dashboards` route record renders `CatalogView` with `meta: { catalogTab: "visuals" }` and the viewer/editor are its children (`dashboard-new` / `dashboard-edit` / `dashboard-view` — names and paths unchanged). CatalogView pins its tab to that meta and mounts the child through a nested `<router-view>` at the head of the `.catalog-detail` panel chain (ahead of any lingering selection), so the tree, tab bar and refresh stay exactly as on the library page; `MenuAccordion` reads the same meta so the rail highlights Catalog → Visuals. The dashboard root pads `--spacing-3`/`--spacing-6` on top of the pane's own padding, matching the library's inset, with a flat header row, a bordered filter strip, and (view mode) the canvas pulled back by the grid's 8px margin so tiles align with the header. On those pages the tree starts collapsed via a session-local `pageTreeCollapsed` flag, separate from the persisted `flowfile-catalog-tree-collapsed` preference the library page uses. KPI tiles (`type: "kpi"`, `KpiTile.vue` + pure `kpi.ts`) bind through the tile's `viz_id` like chart tiles — so filters, refresh nonces and access all reuse the viz plumbing — and compute one empty-`groupBy` aggregate through the saved-viz compute route (`useDashboardComputation`), a second request with the targeting date-range filter shifted back for previous-period deltas; `kpi.value_size` pins the number size (`auto` keeps the container-query fit) and colours reuse the text tiles' top-level `bg_color`/`text_color` and swatch menu.
- Catalog notebook (`views/CatalogView/NotebookPanel.vue`, store `stores/notebook-store.ts`): one header row — the open-notebook tab strip *is* the selector (double-click a tab or Save menu → Rename for inline rename; the `+` dropdown holds New + saved notebooks), controls on the right. The kernel picker and the status banner both derive from the pure `components/notebook/notebookKernelStatus.ts` resolver (docker-off / none / loading / missing / stopped / starting / error / ready) — a selection that no longer exists or is stopped turns the picker amber and the banner offers Start kernel / Clear selection / Manage kernels; add new kernel-state copy there, not as ad-hoc `v-if`s. Cell editors share `pythonScript/notebookEditor.ts`, whose identifier source merges curated catalog-ref entries, Jedi items and prior-cell symbols by label — CodeMirror never dedupes across override sources, so any identifier source that can overlap Jedi must be passed into `createIdentifierCompletionSource` rather than registered separately. Both notebook surfaces (this one and the Python Script node's `pythonScript/NotebookEditor.vue`) share the modules in `components/notebook/`: `cellOperations.ts` (pure structural ops returning `{cells, op, inverse}`), `useCellHistory.ts` (owner-keyed undo/redo of those ops, holding **cell references, not snapshots** — undoing a delete restores the cell's output with it, limit 50), `useCellDrag.ts` (pointer-capture reorder that measures cell bounds **once at activation**, in host-content coordinates so autoscroll can't invalidate them, and never reorders DOM during the gesture — only the `.nb-drop-line` indicator moves), and `editorViews.ts` (owner-scoped `EditorView` registry). **Owner id** identifies one open notebook — the catalog tab's `tabId` via `ownerIdForNotebook`, `node:${flowId}:${nodeId}` via `ownerIdForNode` — and nothing keyed by owner id is ever serialized (not into notebook YAML, not into `python_script_input`). The node editor is **mounted twice** (inline and the fullscreen dialog) over the same `cells`, so owner-keyed state is created and disposed only by `PythonScript.vue` (`loadNodeData` / `onUnmounted`), never by `NotebookEditor.vue`, and the view registry is a per-cell **stack** where the last-registered view wins and `unregisterCellView` removes by identity (unmounting the dialog reveals the inline view instead of deleting the entry). Structural edits in both surfaces go through `cellOperations` + history at one seam — the store action (`_applyStructural`) or the node handler (`applyStructural`) — never by splicing `cells` in a component. `cellPresentation.ts` is the same owner/cell-keyed pattern for code/output collapse: session-local, disposed with the owner, and never serialized — collapse is a view preference, so it must stay out of notebook YAML and `python_script_input`, and it hides with **`v-show`, never `v-if`**, so the `EditorView` (and its text undo history and caret) survives a collapse; `CellActionMenu.vue` is the one ⋯ menu both cell components render. **Focus rules**: insert, duplicate and run-and-advance focus the new-or-next cell after a single `nextTick` via `editorViews.focusCell` (run-and-advance appends a cell only when it ran the last one, and advances on submit without waiting for the run — Shift+Enter runs and moves to the next, Cmd/Ctrl+Enter runs in place), delete focuses the next surviving cell else the previous, a queued focus is dropped when the owning catalog tab is no longer active, and undo/redo deliberately never move focus. A rendered Markdown cell is focusable (its root carries `tabindex="-1"`) and Enter on it reopens the editor. `notebookRuntimeState.ts` carries execution identity and staleness in the same shape — module-level `reactive`, keyed by owner id then cell id, never serialized: a run takes a **ticket** (request id + source revision + session epoch) *before* it is sent and the response may only write to the cell while that ticket still matches, so a superseded request, a deleted cell, or an answer landing after a kernel switch or a **Reset session** (both bump the session epoch) is discarded instead of restoring a result that is no longer current. Downstream cells are marked stale **at submission**, not on completion — a cell that errors part-way has already mutated the namespace, and indices shift mid-batch — and a single run is a batch of one, so `isBatchActive(ownerId)` is the only busy flag either surface has: it is what `structuralDisabled` and the toolbar disables read, and `startBatch` refuses a second Run All synchronously. **Reset session** (never "restart": the kernel process keeps running) clears only this notebook's namespace, and only bumps the epoch and clears outputs when `clearNamespace` actually succeeded — a failed clear surfaces instead of being swallowed. **Column completions** (`pythonScript/dataframeColumnCompletions.ts`) are the one source that runs on a *string* position: `dataframeColumnContext.ts` locates it on the lezer tree and hands back the **receiver expression**, which `dataframeSchemaInference.ts` resolves from the source alone (last assignment before this point, then the method table — anything that could produce a wrong schema stops). The source is **synchronous** except for the first resolution of a catalog reference it has never seen, and dtype + source live in `detail` because `withoutInfo` strips `info`. `useDataframeSchemas.ts` holds the kernel's `last run` frames per owner id and refreshes only on attach, on a settled execution (deferred to a macrotask and skipped while a batch is active, so Run All costs one request) and on an epoch bump — **never per keystroke** — and it is attached/detached by `PythonScript.vue` and `NotebookPanel.vue`, the components that own owner identity. An unresolved receiver falls back to the node's input columns, one row per input (`Int64 · input main`) so two same-named columns keep their own dtype; the catalog surface never guesses a receiver and a subscript never falls back. Jedi **signature help stays off a string position** so the two popups never stack: `lspSignature.ts` gates its schedule and its response on `signatureApplies` (`lspPositions.ts::insideCall` and not `insideString`) — keep any new string-position feature on that same predicate.
- Catalog SQL editor (`views/CatalogView/SqlEditorPanel.vue`, store `stores/sql-editor-store.ts` + `sql-editor-store-persistence.ts`): query tabs are **browser-only drafts** (localStorage `flowfile.sql-editor.v1`: tab text/names, editor height, row limit; run history keeps its older `flowfile_sql_history` key). **A query is stored by saving it as a query virtual table** — the toolbar marker says which: "Draft · kept in this browser only" or "Saved as <table>" / "edited since saved". Saving links the tab (`link.savedQuery` = what the table holds); a linked tab's button becomes **Update virtual table** (`PUT /catalog/query-virtual-tables/{id}`, the backend re-validates the SQL; a 404 unlinks back to a draft), and TableDetailPanel's **Edit SQL** reopens a table via `openVirtualTable` (focusing an already-linked tab so its edits survive; `Open SQL` as an unlinked draft without manage access). Duplicates are always unlinked, so two tabs never update one table. Results and run state live in the store (rows `markRaw`), never in storage, and survive leaving the SQL tab; a run's response lands on the tab that started it (`runSeq` guard). The CodeMirror instance is keyed per tab so undo never crosses tabs (caret is restored from a module-scope map). The inline tab-rename input needs `@keydown.stop`: el-tabs closes a closable tab on Backspace/Delete anywhere inside its label.
- Telemetry consent UI: the one-time consent modal mounts in `AppLayout`, the manage surface is ComputeView's Privacy tab; the backend's `telemetry.yaml` (read via `/telemetry/status`) is the source of truth for consent — never localStorage.
- Catalog-DB snapshots: ComputeView's admin-only Backups tab (`views/ComputeView/BackupsPanel.vue` + `components/settings/DbBackupsCard.vue`) lists and creates snapshots through `api/system.api.ts` → `/system/db_backups`. Read-only by design: no restore/delete/download button — a restore is a manual, app-stopped file copy documented under Deploy & Operate → Database Backups.
- Desktop update prompt: `stores/update-store.ts` runs the launch check (desktop only, skipped in dev) and owns the install phases; `components/settings/UpdateAvailableModal.vue` mounts in `AppLayout` beside the telemetry modal and offers Install now / Remind me later / Skip this version; `AboutDialog.vue`, the home footer's clickable version (`WelcomeScreen.vue`) and the sidebar's Help & more menu all trigger the same check manually — via `composables/useAppUpdate.ts`, the single owner of the resolved app version, the Release-notes link and the check-status copy ("Checking…" / "You're up to date" / "Flowfile X is available" / "Couldn't check for updates"). Off desktop (pip, Docker, the dev server) the same check reads the latest GitHub release through `lib/latestVersion.ts` — the REST API, not the updater's `latest.json` asset, which sends no CORS headers — and "Release notes" then opens that newer release; there is no install step, and no core endpoint is involved. The pure copy, the `shouldPromptForUpdate` gate and the `flowfile.update.ignoredVersion.v1` localStorage key (a skipped version is the only piece of update state kept client-side) live in `components/settings/updatePrompt.ts`. Installing goes download → `POST /system/db_backups` snapshot → install, and **never** through the updater plugin's `downloadAndInstall()`: `desktop.installUpdate()` invokes the Rust `prepare_for_update` command (`commands.rs` → `sidecar::shutdown::shutdown_all`) first, so the sidecars are down before the app bundle they execute from is replaced.
- `src/renderer/app/features/designer/` — flow editor internals (`drawflowExtensions.ts`, `editor/` with FunctionEditor / ColumnSelector / pythonEditor). `editor/EditorSideRail.vue` is the shared fields/functions/parameters rail (extracted from `fullEditor.vue`, which still wraps it for Filter/Gate); it takes the schema to offer as a prop, which is what lets the Formula node point it at a different column set per row. The Formula drawer (`node-types/elements/formula/`) holds an **ordered** list of entries evaluated in sequence — row N autocompletes against the input columns plus the outputs of the non-blank rows before it (`formula.ts::accumulatedColumnsAt`), rows are keyed by a stable per-object uid so a reorder never strands editor text, a reorder is never blocked (a forward reference it creates comes back as a row issue from `POST /custom_functions/formula_chain_check`), and a save ships `functions` only — the legacy single `function` key is dropped from the payload. A row is one flat header line — the output-name field itself, plus a type pill, a right-aligned `1 error` badge and hover-revealed reorder icons — over the editor; there are no per-row label blocks or card borders. Chain-check errors render **inline**: a strip fused to the editor's bottom edge (`.entry-diagnostic`, danger tint; it also paints the editor border and the row's left accent), the collapsed summary line tints danger, and the footer shows an `N errors · jump to next` button that cycles through flagged rows (`rowRefs[...].scrollIntoView()`). A duplicate output column is **not** an error: writing a column twice is a deliberate overwrite, so only the later row gets a muted `Overwrites <col> from formula N` note (`formula.ts::overwrittenOutputs`, computed locally — the backend's `duplicate`-kind issue is ignored for display and excluded from the footer count). `instantFuncResults.vue` is therefore preview-only — a single-row strip with a colored left bar labelled `Preview · <column>` / `Error · <column>`; never route chain issues back through it. Both surfaces are worded by the same backend classifier, so the strip and the banner say the same thing for a parse / missing-column / type failure; the banner adds only what a schema check cannot see (non-boolean predicate, data-dependent cast failures). A `missing_column` issue may carry `suggestion: {kind: "replace_column", from, to}` (`FormulaChainSuggestion`, absent on an older core) — the strip then shows a `Use [<to>]` button that swaps every `[from]` for `[to]` through `FunctionEditor.replaceText` (one CodeMirror transaction, so one undo step), falling back to the pure `formula.ts::replaceColumnReference` when no editor view exists. Collapsing hides the editor and shows the expression beside the name (collapsed state is UI-only, keyed by uid, never saved and never persisted across drawer opens; a chain of ≥ `AUTO_COLLAPSE_THRESHOLD` entries opens folded to the focused row). Collapse uses **`v-show`, never `v-if`** — the editor instance and its undo history must survive — so the host calls the row's `refreshEditor()` (→ `FunctionEditor.requestMeasure()`) after an expand, since CodeMirror caches a zero-height measurement taken while hidden. List rows pass `height="auto"` to `FunctionEditor` (grows between `minHeight`/`maxHeight`, then scrolls, and the line-number gutter is hidden — it costs ~33px a 2-line expression has no use for); every other consumer keeps the fixed 250px default and its gutter. The rail is **collapsible only here** (`EditorSideRail`'s opt-in `collapsible` + `v-model:collapsed`): it folds to a 36px icon strip, which is what buys a list row its width (351px open → 520px folded at the default drawer size). It starts open unless the user folded it before; that choice then holds for the rest of the session via `railFoldPreference`, a `let` in Formula.vue's plain `<script>` block — **module scope, not a component ref**, because the settings drawer remounts the component on every node switch. **Header icon buttons carry `@mousedown.prevent`**: taking focus made the browser scroll the drawer to the button between mousedown and mouseup, which moved the row out from under the cursor and swallowed the click entirely. `components/AlteryxImportDialog.vue` + pure `alteryxReport.ts` (vitest-covered) is the Alteryx `.yxmd` import UI — upload via `composables/useAlteryxImport.ts` → `api/alteryx.api.ts` → `POST /converters/alteryx`, then open the returned `flow_id` and show the conversion report (Alteryx Comment tools arrive as canvas comments, reported `converted` with node type `comment` and no node ids); entry points are HeaderButtons' Create menu, `DesignerEmptyState.vue` and `WelcomeScreen.vue`.

- `src/renderer/app/api/` & `app/services/` — Axios API wrappers; `services/` adds auth/setup/user services, `axios.config.ts` (interceptors, `withCredentials`), and SSE clients (`aiStreamClient.ts`, `aiDiffClient.ts`).
- `src/renderer/app/composables/`, `app/router/index.ts`, `app/i18n/` (only locale `locales/gb.json`), `app/layouts/`.
- `src/renderer/lib/desktop.ts` — the only renderer↔Tauri bridge (invoke/listen wrappers + web-mode fallbacks).
- `src/renderer/config/` — `constants.ts` (baseURL/port resolution), `environment.ts` (NODE_ENV-derived `ENV` flags).
- `src-tauri/src/` — Rust shell: `lib.rs` (entry, `generate_handler!`, lifecycle), `commands.rs`, `sidecar/` (`mod.rs` spawn + port scan, `readiness.rs`, `shutdown.rs`), `menu.rs`, `oauth.rs`, `window.rs`, `state.rs`, `env.rs`.

## Key patterns & conventions
- Path aliases declared in **three** places, keep in sync: `vite.config.mjs` and `tsconfig.json` define `@` (`@/*` glob form in tsconfig) plus `@/api`, `@/types`, `@/stores`, `@/composables`; `vitest.config.ts` defines only bare `@`.
- Router uses **hash history** (`createWebHashHistory`). Routes are lazy `import()`ed; most live under the `/main` `AppLayout` parent with `meta.requiresAuth` (default true). A `router.onError` guard in `router/index.ts` catches chunk-load failures (dev: stale Vite optimize-dep 504s; prod: a chunk a redeploy removed) and reloads **once per target** via a `flowfile:chunk-reload` sessionStorage key, then shows an error instead of looping — don't remove the once-per-target dedupe.
- All desktop-native calls MUST go through `lib/desktop.ts`, which no-ops / falls back in web mode (`isDesktop` guard). Don't import `@tauri-apps/*` directly in view code. New Tauri commands must be registered in `src-tauri/src/lib.rs` `generate_handler!` (the authoritative command list) and wrapped in `desktop.ts`. `desktop.ts` also calls plugin commands directly (`plugin:opener|open_url`, clipboard-manager) — no Rust command needed for those.
- No JSX/TSX: React (`react`/`react-dom` v19, pinned via `overrides`) is only a dynamic `import("react")` inside the `@kanaries/graphic-walker` Vue wrappers. `vite.config.mjs` deliberately omits `@vitejs/plugin-react`; `tsconfig.json` excludes `*.tsx`/`*.jsx`.
- **graphic-walker's map chart must not reach a CDN.** Its bundle injects `<link href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css">` into its shadow root at runtime; the Tauri CSP (`style-src 'self'`) blocks that only in the packaged app (`tauri dev` serves the page from this dev server, where no CSP applies), so the map rendered as an unstyled square on desktop while dev looked fine. `vite.config.mjs`'s `leafletCssLocal()` plugin rewrites that literal to `/leaflet.css` (in the build via `transform`, in dev via an esbuild `onLoad` on the pre-bundle — Vite's transform hook never sees optimized deps) and serves/emits `node_modules/leaflet/dist/leaflet.css` there. The `<link>` keeps its SRI `integrity` attribute, so `leaflet` in `package.json` must stay on the exact version graphic-walker pins — the plugin fails the build on a hash mismatch or when the URL literal disappears (a graphic-walker upgrade), rather than silently regressing.
- **The dev and preview servers send the desktop CSP.** Tauri enforces `app.security.csp` only on pages it serves itself (the packaged asset protocol), never on `devUrl`, so `tauri dev` and `npm run dev:web` used to run with no policy at all and CSP breakage surfaced only in release builds (the graphic-walker map, the `srcdoc` artifact iframe before it). `vite.config.mjs` now reads the policy from `src-tauri/tauri.conf.json` and sets it as `server.headers` (which `vite preview` inherits), adding only Vite's HMR websocket (`ws://localhost:*`). `tests/csp.spec.ts` guards it: the header must equal the config verbatim minus that one addition, the designer/catalog must load clean, and opening a chart must mount graphic-walker with no `securitypolicyviolation` — that last test needs `flowfile_worker` (it skips, not passes, without one), which is why `make test_e2e*` and `e2e-tests.yml` start the worker. Remaining dev/prod gaps the header can't close: `'self'` is `http://localhost:8080` in dev vs `tauri://localhost` packaged, and Docker/web mode (nginx) ships no CSP, so dev is now stricter than web — for anything beyond CSP, `npm run tauri:build:debug` is the real packaged check.
- AG Grid is the **modular** `@ag-grid-community/*` v31 (`ModuleRegistry.registerModules`; not the monolithic `ag-grid-community`).
- **Geometry columns are declared, never sniffed.** Core ships `FileColumn.semantic_type` (`"geometry"` only for a GeoArrow `pl.Extension` dtype; `data_type` stays the castable storage type). Every surface reads that one field through `utils/geometry.ts` (`isGeometryColumn`, `geometryTitle`, `GEOMETRY_ICON`, and `displayDataType`, which shows an `Extension(...)` dtype as its storage token in pills/badges): the preview header pill, `dataPreview/GeometryCellRenderer.vue` (AG Grid `cellRenderer` — Material shape icon + `geometryCellFormatter`'s WKT summary; raw value stays behind the tooltip, Cmd+C and the editor), the stats panel pill, the Select node's data-type cell (`sourceSemanticTypes`) and the formula editor's column badges — all in the Complex badge accent family. Don't reintroduce value-based WKT detection for labelling; `parseWkt` is display-only. **Dormant today**: nothing in the repo produces a `geoarrow.*` dtype, so every surface above is inert until a producer lands and core/worker keep the dtype across the worker hop — a missing pill is not a renderer bug.
- OAuth: the GA connection opens the **system browser** (`desktop.openExternal`) because Google blocks embedded webviews; the generic `open_oauth` command opens a modal Tauri webview window (`oauth.rs`) for providers that allow it.
- **Docs links go through `app/lib/docsLinks.ts`** (`DOCS_BASE_URL` + `docsUrl(path)`), mirrored by `src-tauri/src/menu.rs` `DOCS_URL` — change both together. Paths must carry the `.html` extension (mkdocs runs `use_directory_urls: false`, so a trailing-slash URL 404s). In-app docs always open in the **system browser** via `desktop.openExternal`; never iframe the docs site — the Tauri CSP only allows `frame-src 'self' https://accounts.google.com`, which is why the old `DocumentationView` rendered blank on desktop and was removed. Per-node "Read more" targets resolve through `views/DesignerView/nodeDocsLinks.ts`, a hand-authored `item` → `page.html#anchor` map covering every palette node: **do not derive the page from `node_group`** — the docs pages are hand-maintained and a node can move between them without its palette group changing. Docs headings use the exact `nodes.py` `name=`, with the historical anchor pinned via `attr_list` (`## Read from Database { #database-reader }`) so a rename never breaks this map.
- **`app.security.csp` must take effect verbatim for `script-src`** (`dangerousDisableAssetCspModification: ["script-src"]` in `tauri.conf.json`). By default Tauri hashes every built `.js` asset and appends the `'sha256-…'` list to `script-src` at runtime; per the CSP spec a hash source makes `'unsafe-inline'` ignored, so inline `<script>`s in the `srcdoc` artifact iframe (`ArtifactPreviewModal.vue`: kernel HTML previews, plotly, notebook outputs) rendered styled-but-dead in the desktop build only (`style-src` gets no hashes, hence CSS still applied; web mode ships no CSP). The option disables that hashing for `script-src` only — keep `style-src` modification on and don't fix it by rewriting artifact HTML in the renderer (`data:` isn't in `script-src`; cross-origin `blob:` fetches are blocked from the opaque-origin iframe).
- **CatalogView mounts off one request.** `catalogStore.initialize()` calls `GET /catalog/overview` (tree, flows, tables, stats, favorites, schedules, active runs, scheduler status, default namespace, runs page 1) instead of fanning out to the per-resource endpoints, and is a no-op for `OVERVIEW_TTL_MS` (30 s) after the last load so back-navigation renders the store's data without refetching (`initialize(true)` bypasses; in-catalog mutations refresh their own slices, so the TTL only governs re-mounts — this is UI list metadata, not the version-addressed Delta freshness in core). The per-resource endpoints stay for detail views, mutations and the 20 s active-runs poll. `onMounted` pins `catalogStore.activeTab` from the route **before** awaiting the overview — the store persists the previous visit's tab (default `runs`), so applying the route only after the data arrived rendered that stale tab first and then jumped.
- **Catalog save-target pickers must use `composables/useWritableNamespaces.ts`** (`writableSchemaNamespaces` for store-tree dropdowns, `writableSchemaOptions`/`pruneNonWritable` for self-fetched trees, `isWritableNamespace` for tree rows): it strips system schemas and read-only (`use`-grant) namespaces so users are never offered a save target the backend will 403. Read pickers (catalog reader, apply-model, run-flow, open dialogs) must NOT be filtered this way. Catalog write failures toast via `catalogSaveErrorMessage` (`composables/saveError.ts`), which maps 403 to a friendly read-only message.
- **Canvas auto-connect** (`utils/autoConnect.ts` + `composables/useDragAndDrop.ts`, wired through `Canvas.vue`'s `onNodeDrag`/`onNodeDragStop`): a palette drop, or a drag of a still-**unconnected** node, released within `AUTO_CONNECT_RADIUS` (180 flow px) of a neighbour's facing handle connects the two without a cable drag — existing output → new node's first side input when dropped to the right of the neighbour's centre, new output → neighbour's first free input when dropped to the left; nearest wins, upstream on ties; a split node's unused output is preferred (`preferUnusedOutputs`); `multi` inputs never fill; dynamic-input nodes never take part; an edge-splice hover takes priority over snapping. Candidate rectangles are read from the DOM (`.vue-flow__node[data-id]` → `screenToFlowCoordinate`, like the edge hit-test) because the composable's `useVueFlow()` handle never sees measured `dimensions` (always 0) — measured once per drag (`resetAutoConnectCandidates` at palette drag start/end and `@node-drag-start`/stop, lazily filled on the first tick), since existing nodes don't move while one is dragged. The drag-time cue is the `auto-connect-target` class on the neighbour (`markAutoConnectNode`, same pattern as `markHoveredEdge`). The geometry is pure and vitest-covered (`autoConnect.test.ts`); the same helper is mirrored in `flowfile_wasm/src/utils/autoConnect.ts` — change both. A palette drag over a floating panel (`[data-canvas-overlay]`) or the minimap is refused — `onDragOver` leaves `dragover` uncancelled, clears the cues, and `onDrop` re-checks — since the canvas `<main>` is the drop zone for everything inside it and the node would land hidden under the panel; drag state also resets on `dragend`, because a refused drop fires no `drop` (E2E: `tests/palette-drop.spec.ts`).
- **Canvas handle labels**: a node with >1 handle on a side gets a compact letter plus the declared name as the handle's native tooltip, derived in `utils/nodeHandles.ts` and rendered by `NodeWrapper.vue` (the only component with *labeled* `<Handle>`s — `GroupNode.vue` renders a plain unlabeled pair). `outputHandle.ts::handleLetters` prefers each name's **initial** (join → L/R, filter split → P/F, gate else output → T/E) and falls back to positional A/B/C for the whole side when a name is missing, doesn't start alphanumeric, or two initials would collide — a duplicated letter is worse than an arbitrary one. Two distinct backend fields feed this and must not be conflated: `NodeTemplate.input_labels` is the **static, display-only** per-type list (join → `["Left","Right"]`, custom nodes via `CustomNodeBase.input_labels`), while `NodeInput.input_names` is the **per-instance dynamic-handle** list for `run_flow` only — and `deriveHandles` branches on the latter, so putting static names in `input_names` turns index 0 into a bottom parameter handle and silently drops an input. For a STATIC node that wants a bottom "parameter" pip (gate's control input), use the cosmetic `NodeTemplate.control_input_indices` instead — `buildInputHandles` renders marked indices as `kind: "parameter"`/`Position.Bottom` and `NodeWrapper.vue` already dispatches on `kind`; note the remaining lone side input then loses its letter chip (sideInputs.length rule) by design. VueFlow's `<Handle>` drops fallthrough attrs, so the tooltip is applied with the local `v-native-title` directive, never a plain `:title` (and never on `.handle-label`, which is `pointer-events: none`).
- **Two distinct "share" affordances, keep them visually and verbally apart**: group-based sharing (`components/sharing/ShareDialog.vue`, multi-user grants, gated on `useMultiUser()`) vs the browser **share link** (`components/sharing/ShareLinkDialog.vue` + the "Share link" button in `Header/RightActionCluster.vue` → `GET /editor/share_link`, serverless WASM link — gated only on an open flow, never on `useMultiUser()`; desktop users are its primary audience). The dialog's pure decision logic lives in `components/sharing/shareLinkReport.ts` (vitest-covered); placeholder rows mark their nodes on the canvas via unmarked `setNodeValidation` entries and clear them on close/flow change.
- **Graph mutations: one ordered channel, one request per gesture, core is the source of truth.** `services/mutationChannel.ts` (installed in `axios.config.ts` after the auth interceptors; request interceptors run in reverse) sends ordered requests one at a time in issue order: every non-GET `editor/*` except `editor/code_to_*`, plus `transform/*` and the `ORDERED_PATHS` set (settings, description, reference, custom-node update, flow settings, saves, standard layout, runs). It applies each response's `history` (`flowStore.updateHistoryState`, called only by the channel and `Canvas.loadFlow`; a history naming another flow is dropped), and for every ordered request core refused (any response but a 401) it calls `flowStore.requestReload()`, so an optimistic canvas change always resyncs whatever its call site does. Call sites still catch, to say why: `services/mutationFailure.ts::recoverFromFailedMutation` shows the message and reloads only for failures the channel never saw (network, local errors). A gesture that changes several things is one `FlowApi.applyOperations(flowId, label, ops)` (core's `POST /editor/apply_operations/`: atomic, one undo step), built with `utils/graphOperations.ts`: `connection`/`edgeConnection` are the only `NodeConnection` builders; the removals of one VueFlow tick (nodes, edges and comments) become one `buildRemovalBatch`; a drop or drag onto an edge sends `insert_on_edge` (core replaces the edge in place, so the target keeps the input's position — never delete + connect + connect, which moved the branch to the end of a polars_code/union input list); a new node plus settings uses `addConfiguredNodeOperations`; a save that must drop edges uses `useNodeSettings().saveSettingsDroppingEdges`. Take the channel slot before any await (issue the request first, or `reserveMutationSlot` + `registerPendingEdit` for a debounced edit like the arrow-key nudge burst), change the canvas only after core accepts, and remove edges core already deleted with `removeCommittedEdges`. Core keeps `pos_x`/`pos_y`/`group_id` of the live node on a settings save, so settings payloads carry no position. Handles that depend on settings (Filter split, Gate else, Catalog Writer SCD2) follow the **saved** settings: set on load and in `onAfterSave`, never on an unsaved toggle. The node-id counter never decreases (a redo may still reference an undone id).
- **Undo/redo and the settings drawer.** A press (`UndoRedoControls.vue` → the pure, vitest-covered `views/DesignerView/historyAction.ts::prepareHistoryAction`) flushes pending edits and waits for the channel; with nothing to undo/redo and no pending drawer edits it does nothing and leaves the drawer open. Otherwise it closes the drawer with `{ userEditsOnly: true }`, so the drawer's edits become the step undone; if that close save is refused the press stops and the drawer stays open with its draft (`editorStore.executeDrawCloseFunctionOnce(options, keepOnRefusal)` runs the close once and re-arms it on refusal; `executeDrawCloseFunction()` keeps the registration either way, for Run's pre-run save). After undo/redo the canvas reloads and never patches itself back; `loadFlow` flushes pending edits once, waits for the queue, re-reads if `mutationGeneration()` moved, and keeps viewport and selection when reloading the same flow. **Drawers never save on open.** The drawer session (`composables/settingsDrawerSession.ts`, created per node in `NodeSettingsDrawer.vue`) saves on close only the user's edits (any pointer/key/input event in the drawer body counts) plus, for a never-configured node, what the drawer shows. "Never configured" comes only from the live node's `NodeData.is_setup` in the GET `/node` response the component loaded — `setting_input` may be a display-only proposal (a generated join, a derived advanced filter) or a local default, so a component's draft never decides it.
- Canvas node warning dots (amber) are backend-fed: flow open / settings save / connect / delete / run-completion call `flow-store.fetchSettingsValidation` → `GET /flow/settings_validation` → `results-store.applySettingsValidation`, which owns only entries marked `source: "backend"` and replaces them wholesale per flow. Drawer config checks (WindowFunctions/Unique/GroupBy) still write unmarked entries via `setNodeValidation`. Never re-add per-node downstream validate-func registries — the old client-side missing-column checks were removed in favor of the backend feed.
- Canvas overlay panels (`components/common/DraggableItem/`) persist **user intent only** (dock side + per-axis size/offset/gap, localStorage `overlayPositionAndSize.v4_*`), written solely at gesture end via `stateStore.commitIntent`; the on-screen rect is derived per frame by the pure `layoutGeometry.computeLayout(intent, config, containerBounds, minimized)` against the single shared container measurement `Canvas.vue` registers. **Never persist derived geometry** — that split is the fix for the historical drawer-collapse corruption (150×100 panels). Docked panels resize via splitter edges, pop out only past a 48px deliberate drag, and snap back into a dock when released within 40px of an edge.
- **An open settings drawer is saved before anything leaves it, and a refused save keeps it.** Run (`useFlowExecution.runFlow` → `saveOpenDrawer`) awaits `editorStore.executeDrawCloseFunction()`, which returns the save's boolean (and propagates a throw); a refusal shows a "Flow not started" notification and sends no `POST /flow/run/`. Canvas pane click / double-click, node switch (`Canvas.vue::openNodeSettings`, `Promise<boolean>`) and right-drawer minimize (`DrawerDef.onMinimize` may resolve `false`; `DraggableItem/minimize.ts::nextMinimizedState`) go through `editorStore.saveDrawerBeforeLeave()`: a refused or throwing save keeps the drawer, its node and its edits and warns; the next attempt on that same registration (`refusedCloseFunction` + `refusedWhileRunning`, armed by `rememberRefusedSave`, also by a refused Run) discards the edits instead, so an unfixable setting never traps the user. Concurrent attempts share one in-flight save (`Canvas.vue::openNodeSettings` shares one switch per target node), a successful save clears the close function so `NodeSettingsDrawer.executeCleanup` (now only the fallback for unconditional closes such as a flow switch; it runs the close once via `executeDrawCloseFunctionOnce`, which swallows a throwing save) does not save twice, and any successful save disarms the discard (`disarmRefusedSave`: from `executeDrawCloseFunction`, the drawer's Apply, and `useNodeSettings.saveSettings`, which also covers the output-schema tab's `request-save`). While `isRunning` the server refuses every save: the drawer keeps its edits and warns they can be applied after the run; a second attempt in the same run state discards them. `useNodeSettings.saveSettings` resolves `true` when `nodeRef` is null (nothing to save); `pushNodeData` resolves `true` for a refused save whose settings are unchanged since load (a fresh Read with no file leaves silently; edits held outside `nodeRef`, like Read's typed path, are not protected). Runs and single-node fetches start once per key (`startOnce`), `triggerNodeFetch` ("Run node", Fetch data) flushes the drawer like Run, and a custom node's `pushNodeData` awaits its save and returns a boolean. Pinia does not hot-add new store actions, so a tab loaded before a store gains an action must be reloaded.
- **Cloud storage drawers** (`cloudStorageReader/`, `cloudStorageWriter/`): `data-testid="cloud-path-warning"` (non-blocking, from `utils/cloudPathWarning.ts`: empty or non-URI path, or an upper-case scheme since core's `is_cloud_uri` is case-sensitive; a leading `${param}` stays quiet) mirrors core's run-time path guard; a failed node load shows `node-load-error` with Retry and exposes `canApply` false to hide Apply; failed Delta probes surface through `utils/cloudDeltaProbe.ts::deltaProbeHint` (`delta-probe-hint`, quiet for `NOT_A_DELTA_TABLE`). Both pass `ambient-credentials` to `CloudConnectionPicker`, whose "No connection" option then means this machine's credentials with no endpoint (`no-connection-warning`; worded AWS/Azure/Google Cloud from the scheme of the node's `resource-path`, as core picks them) and is disabled in multi-user mode (`useMultiUser()` ⇒ `/health/status` `mode === "docker"`), where core refuses it. The connection form's auth-method lists live in `views/CloudConnectionView/CloudConnectionTypes.ts::authMethodsByStorageType` (no `auto`: it is a node-level mode the backend rejects on a saved connection); `#aws-profile` shows for AWS CLI only, `#aws-session-token` for Access Key only.

## Gotchas
- `vite.config.mjs` sets `server.strictPort: true` — the dev server fails (not falls back) if 8080 is taken, on purpose so Tauri's hard-coded `devUrl` never points at the wrong port. Dep pre-bundling relies on Vite's own hash-based invalidation; `optimizeDeps.force: true` was **removed** because it deletes the shared `node_modules/.vite/deps` on every start (including a start that then dies on strictPort), leaving a still-running server serving "504 (Outdated Optimize Dep)" for every not-yet-fetched dep. Use `npm run dev:web:force` to rebuild the cache deliberately.
- ESLint here is the **legacy** `.eslintrc.js` (eslint 8 + `vue-eslint-parser`), not the root flat config. `npm run lint` only touches `src/**/*.{ts,vue}` (with `--fix`).
- Sidecar shutdown is a graceful ladder (HTTP `/shutdown` → SIGTERM → SIGKILL) in `src-tauri/src/sidecar/shutdown.rs`; sidecars also self-reap via `FLOWFILE_SUPERVISOR_PID` (set in `env.rs`) + `shared/parent_watcher.py` if the shell is hard-killed. macOS Cmd+Q/dock quit fires `RunEvent::Exit` (not `ExitRequested`), so `lib.rs` matches both. Desktop E2E for this path is a known gap (TODO at top of `tests/web-flow.spec.ts`).
- `lib.rs` builds the main window with `.disable_drag_drop_handler()`, so there is no `tauri://drag-drop` event: OS file drops land in the renderer as ordinary HTML5 `drop` events alongside the internal palette/grid drags. **`text/uri-list` is empty for OS file drops in WKWebView too** — WebKit blanks `file://` URLs out of `DataTransfer` (only http/https/data/blob survive), so no webview hands the renderer a real path. Each desktop platform recovers them differently: **macOS** reads the drag pasteboard (`read_drag_paths` command, `src-tauri/src/drag_paths.rs` → `desktop.readDragPaths()`, prefetched at drag-enter while the drag session is live); **Windows** hands the dropped `File` objects back to the shell via WebView2's `postMessageWithAdditionalObjects` and reads `ICoreWebView2File::Path` off each (`src-tauri/src/webview2_drop.rs` → `desktop.requestDroppedFilePaths()`, answered on the `file-drop-paths` event); **WebKitGTK** has no source at all and falls back to copying the `File` up to core. `desktop.canLinkDroppedFiles` is the renderer-side "can this platform link" flag (dropEffect, overlay hint). Every branch still decides via the single pure resolver `app/utils/fileDropStrategy.ts::resolveDropStrategy` (uri-list first, then native paths, paired by basename) — put new drop rules there, not in the drop handler. Windows note: wry's IPC handler sees our correlation message too and forwards it to tauri, which fails to parse it as JSON and evals one `console.error` in the devtools console per drop — harmless, and deliberately chosen over shapes that reach tauri's invoke-key check (that one `eprintln!`s to the log).
- The per-node settings loader is a **string-interpolated dynamic import** keyed by node-type folder (`GenericNode.vue`, `useDragAndDrop.ts`): renaming a node's settings dir/component breaks loading at runtime (logs `console.error`, no build error).
- **Canvas clipboard & hotkeys are centralized.** All canvas copy/paste flows through `app/composables/useFlowClipboard.ts` (sole owner of the node-copy buffer in localStorage, the `Flowfile nodes · N · <uuid>` clipboard sentinel, and the `isCanvasClipboardTarget` panel denylist) and all canvas shortcuts through `app/composables/useFlowHotkeys.ts` — never add another `document`/`window` clipboard or canvas-keydown listener. Cmd+C/V must stay **ClipboardEvent-based, not keydown**: the Tauri Edit-menu accelerators (`src-tauri/src/menu.rs`) consume the keystroke on macOS but still emit DOM ClipboardEvents. A node paste happens ONLY when the pasted text matches the buffer's sentinel uuid (generic paste) or via the context menu's explicit "Paste Node" action, which deliberately does **no clipboard read** (web Firefox/insecure contexts can't read outside a paste event). Clipboard events targeting `<body>` are classified by the last pointerdown target — non-focusable panel chrome (labels, resizers, WebKit buttons) never takes focus, so the event target alone can't distinguish panel from canvas. An active text selection defers **copy** (only) to the native text copy — the canvas renders selectable text (node-description `<pre>`s) outside any editable element, so `hasTextSelection` is a separate copy-path guard, deliberately not folded into the target predicate (a stray selection must never suppress paste). Every floating panel roots at `DraggableItem`, whose root carries `data-canvas-overlay` — the attribute the denylist keys on; a new overlay component not built on DraggableItem must add it itself.
- **`baseNode/selectComponents/ColumnPickerCard.vue`** is the two-pane column picker behind Group By, Pivot and Unpivot (`node-types/elements/{groupBy,pivot,unpivot}/`): a sortable, filterable, multi-selectable column table above a settings section, in one card whose halves scroll inside their own box so the settings never drop below the fold on a short drawer. The shell owns column and row selection (click / shift / cmd, the same `columnSelection.ts` helpers as Select), HTML5 drag onto the settings pane (`dropZones` show as small pills in the Settings strip while dragging and are targets themselves; a host area marked `data-drop-zone=<value>` is the target under the pointer, elsewhere the pane splits into equal horizontal bands — never large dashed drop areas), edge auto-scroll via `composables/useDragAutoScroll.ts`, the strip-as-sash (drag to pin the split, double-click to reset, chevron to fold, a pin shorter than one row folds; session-scoped `splitPreference` shared by all hosts; the settings open at their content height within 40–55% of the card and the columns take the rest, so filtering never moves the strip) and multi-row removal (strip pill, right-click, Delete/Backspace — the card carries VueFlow's `nokey` class and stops those keys, or Backspace would delete the canvas node; ranges and drags only ever carry columns the filter shows). Hosts render their own rows through the `settings` slot and answer `drop` / `column-action` / `remove-rows`; a host's `reveal` call unfolds and scrolls, and the `reveal` event is where the host flashes the rows. Row selection is positional, so a host that regroups rows on write (Pivot, Unpivot) computes the rows to reveal by name afterwards and clears the row selection; hosts mark rows whose column is gone upstream with `is-stale` and their own scrollers with `data-picker-scroll` so the edge auto-scroll reaches them. The drawer root carries `nokey` too, so Backspace on its tabs or Apply never reaches the canvas. Pure helpers: `columnPicker.ts` (split clamp, `dropZoneAt`, `capUsageChips`, `withoutRows`/`shiftAfterRemoval`) and `columnRoles.ts` (`assignRole`: a single-holder role swaps with a row already in the settings and replaces the holder when the mover is new). Group By keeps its aggregation rows in `groupByLogic.ts` (a blank output name is saved as its `col_agg` default, which is also what the duplicate check counts, and one chip per aggregation covers every row using it); Pivot and Unpivot derive role rows from `pivot_input` / `unpivot_input` and write them back after every edit (`pivotLogic.ts`, `unpivotLogic.ts`; Unpivot renders two marked areas over one flat row index — index keys beside columns to unpivot, each a bordered well that scrolls on its own, stacked under 540px by a container query on the wrapper `.unpivot-layout` because an element cannot query its own width — with the Chosen / By type switch in the second area's header; data-type mode clears the chosen columns on switch, as the save already did, and a null selector means every other column, as the backend reads it). When a host marks areas the shell skips its whole-pane drop outline (`:not(:has([data-drop-zone]))`) so only the area under the pointer lights up. `elements/pivot/{ContextMenu,SettingsSection}.vue` survive only for RecordId. E2E: `tests/group-by.spec.ts`, `tests/pivot-unpivot.spec.ts`.
