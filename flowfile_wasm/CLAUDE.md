# CLAUDE.md - flowfile_wasm

Browser-only, Pyodide-powered build of the Flowfile visual designer: a Vue 3 + VueFlow editor where Polars runs entirely in WebAssembly, with no backend. Package-specific notes; see the root `/CLAUDE.md` for monorepo-wide setup, build, lint, ports, and cross-package contracts.

## Role
A fully self-contained, in-browser ETL editor. Unlike the desktop/web app, it does **not** talk to `flowfile_core`, `flowfile_worker`, or `kernel_runtime` — there are no axios/fetch backend calls. All execution happens client-side: a Pyodide runtime (CDN `v0.27.7`) loads `polars` + `pydantic` plus a Python execution engine that lives as a real package under `src/pyodide/engine/` (written into Pyodide's virtual filesystem at startup, then re-exposed as a flat global namespace so the `flow-store.ts` bridge's bare-name calls resolve).

Two consumption modes:
- **App** (`npm run dev` → :5174, `npm run build`): SPA mounted via `src/main.ts` + `src/router/index.ts` (routes `/` and `/embed-example`).
- **Library** (`npm run build:lib` → npm package `flowfile-editor`): entry `src/lib/index.ts`, exports the `FlowfileEditor` component + `FlowfileEditorPlugin`. Host apps embed it, pass `inputData`, drive it via a template-ref API (`executeFlow`, `executeNode`, `exportFlow`, `importFlow`, `setInputData`, `getNodeResult`, `clearFlow`, `initializePyodide`) and listen to `ready` / `output` / `execution-complete` / `error` events. Type/schema shapes in `src/types/index.ts` are *structurally* aligned with `flowfile_core` schemas for save-file compatibility only — no runtime coupling.

Execution contract: nodes are stored as Polars **LazyFrames** keyed by `node_id`; schema is read via `collect_schema()` without collecting; previews are materialized on demand and LRU-cached (`_preview_cache`). The orchestrator (`src/stores/flow-store.ts`) topologically sorts the DAG (`getExecutionOrder()`) and calls `execute_<type>(...)` Python functions through `pyodideStore.runPythonWithResult(...)`.

## Layout
- `src/stores/pyodide-store.ts` — Pyodide bootstrap; `import.meta.glob`s the `src/pyodide/engine/` package, writes it into Pyodide's FS, imports it, and dumps its full namespace into Pyodide globals.
- `src/pyodide/engine/` — the Python execution engine as a real package: `state`/`dtypes`/`errors`/`preview`/`validation`, `nodes_*` executors, `schema_propagation`, with `__init__.py` re-exporting the public API. Ruff-linted and pytest-tested (`tests/python/`); the same files load in the browser and under pytest.
- `src/stores/flow-store.ts` — DAG state, `getExecutionOrder()` topological sort, `executeNode`/`executeFlow`, the JS↔Python `toPythonJson()` helper, IndexedDB persistence orchestration.
- `src/stores/file-storage.ts` — hybrid file persistence: sessionStorage (<5MB) + IndexedDB (≥5MB) for CSV inputs and output downloads.
- `src/stores/schema-inference.ts` — pure-TS output-schema inference (no Python) for live previews; returns `null` for `polars_code`/`formula`/`pivot`/joins-without-right-schema (can't infer → triggers lazy execution).
- `src/components/Canvas.vue` — VueFlow canvas + node palette (the `nodeCategories` ref is the authoritative category/node list) and the `getSettingsComponent` type→panel map.
- `src/config/nodeDescriptions.ts` — node titles/intros for settings panels (one key per node type).
- `src/config/polarsCompletions.ts` — CodeMirror Polars autocompletion for the Polars Code node.
- `src/components/nodes/` — per-node settings panels (`*Settings.vue`) + `FlowNode.vue`, including `exploreData/` (Graphic Walker).
- `src/lib/` — embeddable library surface: `index.ts` (exports), `FlowfileEditor.vue`, `plugin.ts`, `types.ts`.
- `src/composables/useCodeGeneration.ts` — generates standalone Python/Polars scripts from a flow (CodeGenerator modal). Exports `FlowToPolarsConverter`; only the members the plain-Python flavour overrides or calls are `protected`, the rest stay `private` — the protected set documents the actual subclass seam. Also exports `explainNodePolars(options, nodeId)` for the drawer's "same step in Polars" block: whole-flow `convert()` then `explain(nodeId)`, which slices the node's **raw** (pre-fusion) emission from `nodeSpans` and renames it with `explainRename`, computed by `planExplainNames` as an **unfused** naming pass (all emissions as survivors) — the same pass the plain flavour uses, so the two stacked drawer blocks bind identical names (`filtered_1`/`filtered_2`), even where the fused script would have said `filtered`. `explain()` saves/restores `lastNodeVar` around `applyRenames` (which mutates it).
- `src/composables/usePlainPythonGeneration.ts` — the **teaching flavour**: the same flow with no dataframe library (see Key patterns).
- `src/utils/iconUrls.ts` — explicit icon imports (inlined as base64 in lib build).

## Key patterns & conventions
- **Execution is explicit-only — data runs ONLY when the user clicks Run.** Node execution (`executeNode` / `executeNodeWithUpstream` / `executeFlow` in `flow-store.ts`) may be triggered **only** by deliberate Run actions: **Run flow** (toolbar / Ctrl+E / lib `run` API), **Run Now** (node context menu), **Apply** (settings drawer), and **Fetch data** (the Table-preview button). Selecting a node, opening the Settings or Table panel, single-/double-click, drop, and paste must **never** call an execution path — opening the Table shows existing rows or a placeholder, not a fresh run. `fetchNodePreview` is **preview-only**: it materializes already-computed data, stays gated on `result.success`, and must never reach an `execute_*` bridge. Regression guard: `tests/unit/no-auto-run.test.ts`.
- **No `.collect()` unless required.** Nodes chain LazyFrames; only `output`, `pivot`, `explore_data`, and `polars_code` materialize. Mirror this when adding nodes.
- **Canvas overlay panels** (`components/common/DraggableItem/`) mirror the desktop app's intent-based system: localStorage `overlayPositionAndSize.v4_*` stores user intent only (dock + per-axis size/offset/gap, written at gesture end via `stateStore.commitIntent`); rects derive per frame from the container `Canvas.vue` registers via `registerContainer`. Old v3 records migrate once. wasm extras kept on top of the port: `onClose` close button, `footer` slot (settings Apply bar), `actions` slot (extra header buttons, right of the tab strip — the Code panel's run/refresh/export), `flushContent` (hand the whole content box to the slot: no padding, no scroller), and minimized state persisted under `overlayMinimized.v4_*` (the desktop app treats it as transient). Never persist derived geometry.
- **Plain-Python (teaching) flavour** (`usePlainPythonGeneration.ts`): a second mode in the Code panel that rewrites the flow as `list[dict]` + `for` loops, plus the "How would I write this myself?" panel in `NodeSettingsWrapper.vue`. Both are double-gated by the `teachingMode` prop and the Learning mode setting (the Learning mode bullet below is the spec). The panel stacks the same step in Polars under the plain loop (`explainNodePolars`; shared naming pass ⇒ identical variable names), skipped for `polars_code` nodes and whenever the plain hint path is active; for a stubbed node (`NodeExplanation.isStub`) the plain block is hidden entirely and the Polars snippet is the step's only code, introduced by a neutral label. Formula snippets start on the `simple_function_to_expr` runtime fallback and upgrade to the translated `pl.` expression once `pyodideStore.isReady` — the watcher translates **all** formula nodes (untranslated fallbacks change fusion and other nodes' names) and never triggers Pyodide init (`useFormulaTranslation.ts`, shared with CodeGenerator.vue). The generated script is newspaper-ordered (`run_etl_pipeline()` first, the helpers it calls below it) and loop temporaries take the plain name (`groups`, `seen`, `wanted`); a node-id suffix appears only on a real collision, and `temp()` also refuses `RESERVED_NAMES` so a loop temporary can never shadow a Python builtin. Rules that hold it together: (1) **`PLAIN_PYTHON_NODE_TYPES` is derived** from the `PLAIN_HANDLERS` table (`as const satisfies Record<string, keyof FlowToPlainPythonConverter>`) — never hand-write a second list, or an inherited Polars emitter leaks `pl.` into the output; (2) **chain fusion is off** — `renderBody` is overridden because you cannot pipe two `for` loops together; (3) an emitter that cannot honour a setting throws `PlainPythonUnsupported`, the half-written block is rolled back and a **done-by-the-canvas note** takes its place — a short comment quoting the rule plus a passthrough binding (`var = input`, or `[]` for a source), never a fake `raise NotImplementedError` implementation — so the plain flavour never refuses a whole flow the way the Polars one does and every script stays runnable end to end; URL CSV reads are real, not notes (`read_csv_file` fetches http(s) sources with urllib); (4) **semantics are matched against `src/pyodide/engine/`, not flowfile_core** — the two genuinely differ (aggregate set, join suffixing, `unique` strategies). Correctness is pinned by `tests/unit/plain-python-parity.test.ts`, which runs each fixture through the real `engine.build_*` calls (`tests/python/engine_flow_runner.py`) and through the generated script and diffs the rows; it skips cleanly when no CPython with Polars is found (`FLOWFILE_TEST_PYTHON` overrides the search). Known deliberate gaps: the CSV reader does not parse dates, which the engine's `try_parse_dates=True` does — it is called out in the generated helper as an exercise; and the pivot loop has no equivalent of the engine's `max_unique` 200-column cap, so a script can succeed where the canvas refuses.
- **Learning mode** (`stores/learning-store.ts`, graduation-cap toggle in `IconRail.vue`, persisted under `flowfile-learning-mode`) is the *user* setting; the embeddable `teachingMode` prop is the *host* setting. Prop off ⇒ the capability does not exist. Prop on + setting **off** ⇒ the teaching surfaces stay hidden: the Code panel is a tab-less Polars view whose header carries a graduation-cap opt-in button (the lib's only opt-in affordance — embedders have no icon rail), and node settings show no explainer. Prop on + setting **on** ⇒ the two tabs and the per-node explainer appear and the panel opens on **Python walkthrough**. The landing mode resolves on panel open, and the panel also watches the setting while open (rail toggle ⇒ mode follows), so the toggle always has a visible effect. Gate tests: `tests/components/NodeSettingsWrapper.test.ts`.
- **The Code panel has exactly two tabs** (`CodeGenerator.vue`), `polars` and `walkthrough` — shown only while Learning mode is on; otherwise the panel is tab-less Polars — one CodeMirror instance, never `v-if`'d, whose doc is swapped between them (`flowfile-codegen-mode` migrates the pre-merge `'plain'` value, and is ignored while Learning mode is off). Walkthrough mode splits the panel into a **bench** (the editable, runnable script with the current step highlighted) and a **margin** (`StepMargin.vue`: Why / Data / Output) across a draggable divider (`flowfile-codegen-split`, per-axis, columns above 880px of *panel* width; the column rules are scoped `.workbench.split.is-wide` so the tab-less Polars view can never inherit a phantom margin column). Step chips live in a fixed-height rail, so stepping can never resize the editor. Per-step data comes from the **canvas run**, not from re-executing the script: `loadStepData()` in `CodeGenerator.vue` maps each step's varNames back to node ids and fills the `CapturedTrace` shape (`usePlainStep.ts`) from `flowStore.fetchNodePreview` — strictly preview-only (gated on `result.success`, never reaches an `execute_*` bridge, so the no-auto-run contract holds), and the Data tab says "Run the flow to view the data produced" until the user runs it. The old in-browser instrumented trace is gone from the component; `usePlainTrace.instrumentScript()` / `buildTraceCode()` remain as the CPython-tested capture contract exercised by `plain-python-walkthrough.test.ts`. **Compare to canvas** (`usePlainTrace.compareTables()`) checks row count, column sets and cell values over the first 50 preview rows of the node the script's return value maps to (the last walkthrough step, not an arbitrary terminal), and its "run the flow first" guidance is a neutral `info` status, not a red verdict. The header's Refresh **preserves edits** (stashes them as the draft; Reset is the only discard path), and a `flowFingerprint` watcher shows a "flow changed — Refresh" banner instead of letting the script drift silently. Both CodeMirror instances set `:indent-with-tab="false"` (the vue-codemirror default is a Tab keyboard trap), and the glossary adds a cursor/tap tooltip on coarse-pointer devices (`COARSE_POINTER` in `usePythonGlossary.ts`); there is deliberately no "hover any name" hint in the bench head. The panel **is a `DraggableItem`** (`id="code-panel"`, docked right, 620px default, `heightBehaviour="scale"`), so edge-resize, drag, fullscreen, minimize and Reset Panel Layout come from the shared overlay system and its intent persistence — there is no second geometry system and no per-panel localStorage key. Its two modes are the DraggableItem header tabs, so switching never teleports it. It stacks with the other panels (`PANEL_BASE`..`FULLSCREEN`), which means the last-clicked of Code / Node settings wins and `LayoutControls` (`FLOATING_WIDGET`) stays on top of both; the only special case left is `AppLayout`'s prominent "Try Demo" CTA, hidden while the panel is open because it is viewport-fixed over the header buttons. The panel keeps the canvas in step via `syncCanvasToStep()` — `flowStore.selectNode()` (never a bare `selectedNodeId` assignment: preview memory release and the Table panel's gated fetch live in selectNode) plus a `focus-node` emit that `Canvas.vue`'s `panToNode` answers with a 300ms `setViewport` at the current zoom — centred on the **unobstructed slice** of the canvas (`layoutGeometry.unobstructedRect` cuts each measured `.overlay` rect away from whichever side leaves the most room), never on the pane middle the docked panel is covering; the sync guards against steps whose node was deleted, and is re-fired explicitly after regeneration because the value-keyed watcher misses a reopen landing on the same node. That is the canvas↔code link, and why the panel docks beside the canvas instead of covering it. While the panel is open, a double-click on empty canvas closes it (`onPaneClick` checks `event.detail >= 2`; `zoomOnDoubleClick` is disabled while open AND for a beat after closing — the prop flips back before the browser's native dblclick lands, so without `suppressDblClickZoom` the closing gesture would also zoom). A stashed draft carries its `draftRanges` (`allStepLines`) so a restored edited buffer is reseeded from its own mapped ranges, never the generator's line numbers; Refresh from the Polars tab leaves the stashed draft alone. `isWide` (bench/margin as columns) is a `ResizeObserver` on the panel body at 880px, now reachable by dragging rather than only by viewport size. **The walkthrough itself has two flavours** — a `Plain Python | Polars` segmented toggle in the bench head (`flowfile-walkthrough-flavour`; `setFlavour` is the flavour ref's ONLY writer and always routes through `generateCodeFromFlow`, which is what lets steps/trace/run state stay single). The Polars flavour comes from `usePolarsWalkthrough.ts` (`buildPolarsWalkthrough`): an **unfused** subclass of `FlowToPolarsConverter` that mirrors the plain renderBody/buildFinalCode pattern and names from the same unfused pass — so the plain walkthrough, the Polars walkthrough and the drawer's `explainNodePolars` snippets all bind identical variable names — write steps included, via a `SINK_PASSTHROUGH` remap to the input's name; the one divergence is `external_output`, which is a Polars-only step (plain emits nothing for it). Test-pinned in `tests/unit/polars-walkthrough.test.ts`, incl. CPython proof that the unfused script equals the fused export and that an instrumented run's steps match the engine. `generated`/`draft`/`draftRanges` are writable computeds over per-flavour slots (per-flavour `generated` keeps `edited` sane during the async polars build, and per-flavour ranges are what keep seedNow's length guard sound — both builders emit one step per node). Flavour switches preserve the current step **by nodeId**, and the walkthrough branch resets trace state BEFORE the builder (the flavours share variable names, so stale varName-keyed capture tables would "match" the other script); a throwing builder also clears `walkthrough` and sets `generated = code` so the placeholder can never be stashed over a real draft. The ▶ run harness is **type-aware** (list → as-is; LazyFrame → collect; DataFrame → to_dicts), serves both flavours, and bridges the wasm build's gaps for the in-browser run only: `stageReadFiles()` writes each Read node's text into the FS and substitutes quoted URL literals with the staged name in the executed copy (the buffer and export keep the URL; wasm Polars has no `cloud` feature), and the harness temporarily patches `pl.scan_csv` (file-backed scans **fatally abort** the wasm runtime at collect — read via `read_csv(StringIO(...)).lazy()` like the engine) and `pl.LazyFrame.sink_csv` (no thread spawn — collect + buffer write), restoring both in `finally`. `ensureScriptPackages` micropip-installs `EXPR_TRANSFORMER_PACKAGE` when the buffer needs it. The Polars flavour's Why tab is **not** the plain concept cards (steps carry `concept: ''`): it renders `POLARS_DOC_FOR_NODE` from `usePolarsWalkthrough.ts` — a one-sentence per-operation blurb plus the Polars reference link. The glossary carries the Polars vocabulary with dual-context rewordings for `join`/`sort`/`sum`/`min`/`max`/`len`/`median`/`str`/`values`. Export filenames: `pipeline_plain_python.py` / `pipeline_polars.py` / `flowfile_pipeline.py` (Polars tab).
- **The concept background is opt-in** (`CONCEPTS` in `usePlainPythonGeneration.ts`): collapsed by default behind a labelled "Why does it look like this?" affordance, because plenty of readers want the code and the rows and no prose. Turning it on adds the Why tab and persists in `learning.showBackground` (`flowfile-codegen-background`); stepping never changes the active margin tab. A card may end with an optional `another` footer (a stdlib road + one docs.python.org link, rendered quieter than the takeaway) — deliberately rare, and the exact card set is test-pinned so footers do not accrete until they stop being nudges.
- **`useStepHighlight.ts` holds every step as document offsets**, mapped through `tr.changes` on each transaction, re-seeded (`seedStepsIn`) only when the doc is replaced programmatically. That is what lets the highlight survive the reader editing the script, and why the header's line numbers are read back out of the field (`stepLines`) instead of off `PlainStep.lineStart` — the label and the paint cannot disagree.
- **Adding a node type** touches: `nodeCategories` + `getSettingsComponent` in `Canvas.vue`, `nodeDescriptions.ts`, a `*Settings.vue` panel, `NODE_TYPES`/types in `src/types/index.ts`, an `execute_<type>` Python fn in the matching `src/pyodide/engine/nodes_*.py` module (re-exported from `engine/__init__.py`'s `__all__`), a `case` in `executeNode` (`flow-store.ts`), and usually `useCodeGeneration.ts` + `schema-inference.ts`. For `usePlainPythonGeneration.ts` you always add a `NODE_EXPLANATIONS` entry (a test fails without one) and *optionally* an emitter + `PLAIN_HANDLERS` row — with no emitter the node becomes a done-by-the-canvas passthrough note, which is the right call for anything expression-driven. The Polars walkthrough flavour also wants a `POLARS_DOC_FOR_NODE` entry (blurb + reference link) for its Why tab. An emitter also needs a `CONCEPT_FOR_NODE` entry pointing at a `CONCEPTS` key (also test-enforced), because the walkthrough shows the pattern, not the node.
- **Pyodide is loaded once, lazily** from a CDN `<script>` tag injected in `initialize()`; `usePyodideStore.isReady` gates all execution. `numpy` is deliberately avoided — previews use native Polars `.rows()` to keep memory low.
- **Memory discipline:** `del` materialized DataFrames and call `gc.collect()` after heavy ops; honor `GW_MAX_ROWS` (100k) and pivot's `max_unique` (200) caps.
- **JS↔Python bridge:** large CSV/text content crosses via `setGlobal('_temp_content', …)`; binary (xlsx/parquet-IPC/Arrow) crosses via `setGlobal('_temp_bytes', Uint8Array)` with `.to_py()` **in the bridge string** (engine signatures take plain bytes-like, so pytest passes `bytes`). Node settings always cross inline as `json.loads(${toPythonJson(node.settings)})`. Results return through `runPythonWithResult` (deep-converts Maps → plain objects) — **except bytes**, which don't survive `toJs()`: the engine stages them in `state._output_binaries` and JS pulls once via `runPythonGetBytes('take_output_binary(id)')` (`PyProxy.getBuffer('u8')`).
- **File content is a tagged union** (`src/types/file-content.ts`): `{kind:'text',data:string} | {kind:'binary',data:Uint8Array,format:'excel'|'parquet'|'arrow-ipc'}`. Binary wrappers are `markRaw`'d, always persist to IndexedDB (structured clone, no base64), never enter sessionStorage JSON / saved-flows entries / the persisted clipboard, and restore via `largeFileNodeIds` + re-pick.
- **Heavy deps load lazily on first use, never at boot:** Excel = micropip (`ensurePyPackages(['openpyxl==3.1.5'])` / `XlsxWriter==3.2.0` — pins must match `tests/python/requirements.txt`); Parquet = `parquet-wasm@0.7.1` esm from jsdelivr via a **bundler-opaque** dynamic import (`src/utils/parquet-bridge.ts`; a literal https: `import()` in the published lib breaks webpack5/esbuild embedders — guarded by `tests/unit/parquet-bridge.test.ts`).
- **Parquet never touches Python as parquet:** the wasm polars wheel has parquet compiled out but IPC kept. JS (parquet-wasm) converts Parquet ⇄ Arrow IPC stream bytes; the engine only runs `pl.read_ipc_stream` / `write_ipc_stream(compat_level=oldest)`. `_clean_strings_for_export` (nodes_io.py) rebuilds String/Binary columns before IPC export — the wasm build panics ("capacity overflow") converting view-type columns whose buffers came through IPC import or the excel reader.
- **Library build:** `assetsInlineLimit: 100000` inlines icon PNGs as data URIs (avoids `import.meta.url` breakage in lib mode); `vue`/`pinia` are externalized (rollup `external`) and declared as peer deps (`pinia` optional).

## Running / entry points
```bash
cd flowfile_wasm
npm install
npm run dev        # app dev server → http://localhost:5174
npm run build      # app build (vue-tsc --noEmit && vite build)
npm run build:lib  # publishable flowfile-editor lib (BUILD_MODE=lib)
npm run build:all  # both
npm run preview    # preview built app
```

## Testing
Vitest, `happy-dom` env, config in `vitest.config.ts` (alias `@` → `src`, setup `tests/setup.ts`). IndexedDB is mocked via `fake-indexeddb`; sessionStorage/Blob mocked in setup. Tests live in `tests/` (`unit/`, `integration/`, `components/`).
```bash
npm run test          # watch
npm run test:run      # CI / one-shot
npm run test:coverage # v8 coverage
```
Note: the "integration" suite (`tests/integration/pyodide-execution.test.ts`) validates the *structure* of the embedded Python logic — it does **not** boot a real Pyodide runtime.

`tests/unit/plain-python-parity.test.ts` shells out to a CPython with Polars (env var `FLOWFILE_TEST_PYTHON`, else `python3`/`python`, else a `flowfile-*` Poetry venv). Without one it reports **skipped**, not passed — if you see `44 skipped`, nothing was actually compared.

## Gotchas
- Pyodide needs `SharedArrayBuffer`, so the page must send COOP/COEP headers (`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`). The dev server sets these in `vite.config.ts`; embedders must set them on their host page or Pyodide fails to load.
- Pyodide is pinned to **v0.27.7** in `pyodide-store.ts` — the last release with Polars support; bumping it likely breaks `loadPackage(['polars', 'pydantic'])`.
- The Read File node handles CSV, Excel (.xlsx via openpyxl, explicit `engine=` — calamine/fastexcel has no wasm wheel; polars 1.18 `read_excel` has **no row-offset kwarg**, `start_row` is a `.slice()` in the engine) and Parquet (JS-decoded to IPC), plus remote URLs (plain CORS; COEP does not block `fetch`). Output writes CSV, Excel (xlsxwriter → `take_output_binary`) and Parquet (IPC staging → `ipcStreamToParquet`). `file_type:'json'` from core-saved flows fails with a clear message. The catalog stays CSV-only.
- The Python engine is a real package under `src/pyodide/engine/`, written into Pyodide's virtual FS by `setupExecutionEngine()`. **Flat-namespace contract:** `flow-store.ts`'s bridge runs bare Python that references not just the public `execute_*` functions but also engine **internals** (e.g. `_lazyframes`) and the modules the engine imports (e.g. `gc`). So the bootstrap doesn't just `from engine import *` — it **dumps the package's entire namespace** (every submodule's non-dunder names) into Pyodide globals, reproducing the original single-module `exec`-into-globals behavior. Consequence: CPython unit tests (`tests/python/`, pinned to Pyodide's Polars 1.18.0) verify engine *logic* but **cannot** catch a broken browser namespace — the real-Pyodide smoke test (`tests/pyodide-smoke/smoke.cjs`, CI job `pyodide-smoke`) replays the bridge against actual Pyodide and is the guard for that. The same files are the source of truth for the browser, pytest, and the smoke test.
- `optimizeDeps.exclude: ['pyodide']` and `include: ['react', 'react-dom/client', '@kanaries/graphic-walker']` are load-bearing (Graphic Walker is React, embedded inside Vue). `pyodide` is not an npm dependency at all — it's CDN-loaded.
- The node palette is defined by the `nodeCategories` ref in `Canvas.vue` — that is the authoritative list of categories and node types (don't trust counts written elsewhere). Several entries are `available: false` placeholders (core-only nodes with a `docsAnchor` link, no wasm implementation). Hosts can filter the palette via the `nodeCategories` prop, so marketing copy says "20+". The library exposes an Arrow host contract: `inputData` accepts `Uint8Array` (Arrow IPC / Parquet, explicit `format` preferred over the PAR1 sniff) and `getNodeResultArrow(nodeId)` pulls a node's frame as IPC bytes via `get_node_arrow`.
- `preview` is a **legacy** node type, migrated to `explore_data` on load (`flow-store.ts`). `PreviewSettings.vue` and an `execute_preview` Python fn still exist but are not in `NODE_TYPES`, the palette, the `getSettingsComponent` map, or the `executeNode` switch. The live sample/preview node is `head` (Take Sample).
